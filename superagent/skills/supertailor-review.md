# Superagent supertailor-review skill

> **Bulk reads** (`rules/subagents.md`): any lookup expected to pull more than
> ~20k tokens of raw tool results (~10k once the economy level resolves to `full`;
> multi-entity sweeps, whole email thread trees, long histories or archives) runs
> in a subagent (`Explore` read-only / `general-purpose` if it must write) that
> returns only the synthesis — named facts, quotes, `file:line` pointers — never
> raw dumps into the main transcript.


This is the runnable shell of the Supertailor agent. The full role definition is in `supertailor.agent.md`. The destination-classification + safeguard contracts are referenced from there.

## 1. Hygiene pass

Mechanical, reversible repairs.

Per `supertailor.agent.md` § "Hygiene pass":

1. **Template compliance**: every `Domains/<domain>/` has the four files; every file carries the maintenance banner; every `history.md` has the right `## Log` shape with H4 date headers; every `status.md` has `## Status / ## Open / ## Done` blocks.
2. **Orphan detection**: folders with no index row; index rows pointing nowhere; cross-references to non-existent ids.
3. **Memory staleness**: `context.yaml.last_check` older than 7 days; `model-context.yaml` not updated this month; cadence skill stale per the documented intervals.
4. **Cadence adherence**: surface "you said weekly review weekly but the last one was 23 days ago — drop the cadence preference, or is something off?".
5. **Schema integrity**: validate every `_memory/*.yaml` against its `schema_version` (delegate to `tools/validate.py`).
6. **Watchlist health**: every `_memory/watchlist-state.yaml` row with `error_streak > 0` or `status: evicted` surfaced with its `last_error` / `evict_reason` and one-line "what to fix" (per `contracts/watchlist.md`).
7. **Custom-overlay scaffold**: ensure `_custom/{rules,skills,agents,templates,tools,watchers}/` exist; create empty if missing.
8. **Improvement-ideas catalogues exist**: verify the two hand-curated idea catalogues named in `supertailor.agent.md` (hygiene-pass item "Improvement-ideas catalogues exist") are present and parseable, with the tier headings that file lists. They are mandatory inputs to step 3 below; missing files silently degrade Supertailor output. Surface as `needs-attention` (not auto-fixable — both are hand-curated).
9. **Signal-capture health**: near-zero rows in `action-signals.yaml` + `personal-signals.yaml` while `user-queries.jsonl` is dense over the same period → capture-adherence failure (the session-end sweep in `contracts/capture.md` § 7.2a is not running); surface as `needs-attention`.
10. **Memory-routing check**: run `uv run python -m superagent.tools.memory_routing_check --since <last review>`; exit 1 → flag the reported files for migration per `rules/memory-routing.md`.
11. **World-graph consistency**: run `uv run python -m superagent.tools.world validate` (per `contracts/world-graph.md` § 5); exit 1 → list the dangling edges as `needs-attention` with the one-line fix `uv run python -m superagent.tools.world rebuild` (the graph is derived; a rebuild is always safe).

For each finding, list it; ask `approve all / approve some / decline all`. The Supercoder applies approved repairs and commits — `git revert` is the rollback path for `superagent/` writes; `workspace/` writes rely on the file-by-file safety nets in `superagent/docs/faq.md`.

## 2. Strategic pass

Pattern detection on usage data.

Per `supertailor.agent.md` § "Strategic pass":

1. **Friction patterns** from `user-queries.jsonl` (clusters of similar queries; skip rows tagged `synthetic: true` — harness-generated turns, not the user) and `action-signals.yaml` (`target: tailor` rows still `status: captured`).
2. **Skill utilization** — skills not run in 30 days (deprecation candidates) and skills run with high frequency (optimization candidates).
3. **Domain utilization** — silent domains (archive candidates) and overactive domains (split candidates).
4. **Ingestor utilization** — sources that ingest but whose data is never queried (disable candidates) and not-configured sources for whose data the user keeps asking (recommend setup).
5. **Auto-capture rule misses** — manual signals captured shortly after an ingest run (likely missed auto-capture rules).
6. **Output / template critiques** from `action-signals.yaml.kind: artifact-critique`.

Each strategic finding becomes a row in `_memory/supertailor-suggestions.yaml` with full context (problem, evidence, suggestion, implementation_sketch, effort, risk, destination).

## 3. Consult the improvement-ideas catalogues

Before drafting any new suggestion, the Supertailor MUST check whether the friction patterns from step 2 match a pre-analyzed entry in one of the two hand-curated idea catalogues that `supertailor.agent.md` names under "Catalogue lookup (mandatory)" — one of structural-improvement options, one of token-efficiency / cache / latency improvements. This avoids re-deriving ideas the framework has already thought through, and surfaces "this isn't a one-off; it's been catalogued since <date>".

### 3a. Read the catalogues

Use a TOC-first read pattern: read each catalogue's section index, then jump only to the relevant tier sections. Do not load whole catalogues into context.

### 3b. Match friction → catalogue entry, then check for a prior retirement

For each friction theme from step 2, check whether a catalogue entry addresses it. Typical pairings: repeated "what changed since I last looked" → differential snapshots; repeated "find that note about X" → full-text search / embeddings; "where did this fact come from?" → provenance; slow or expensive sessions → the perf catalogue's quick-wins tier.

Several catalogued entries were shipped and later pruned for zero usage — `docs/roadmap.md` § Released lists every retired artifact by name in each prune release's row (0.8.0 onward). Before citing any catalogue match, check the Released table for a prior retirement; if found, the suggestion MUST cite the prune in `evidence` and show fresh usage signal before re-proposing — never re-propose a pruned feature on the catalogue entry alone.

### 3c. Cite the match in the suggestion

When a friction theme matches a catalogue entry, the resulting `supertailor-suggestions.yaml` row MUST cite it:

- `evidence`: append `" — matches catalogue: <catalogue short name> § <entry id> (<entry title>)"`.
- `implementation_sketch`: prefer pointing at the catalogue's existing sketch over re-deriving it.

### 3d. Surface gaps

If a friction theme matches NO catalogue entry, note it in the report under `### Catalogue gaps` with a one-line description. Do NOT auto-add to the catalogue (it's hand-curated). The user can promote during the review or ignore.

### 3e. Do not mutate the catalogues

The catalogues are READ-ONLY for the Supertailor. New ideas surfaced here go into `supertailor-suggestions.yaml` as normal; promoting them into the catalogue is a manual user step.

## 4. Destination classification

For every suggestion before write:

1. Supertailor classifies: `destination: superagent` (generic) or `_custom` (user-specific).
2. **Token-scan safeguard** — scan suggestion body against:
   - `_memory/contacts.yaml.contacts[].name` and `.aliases[]`
   - `_memory/domains-index.yaml.<domain>.id`
   - `_memory/assets-index.yaml.<asset>.name` and `.serial`
   - `_memory/accounts-index.yaml.<acct>.name`
   - Address-fragment / license-plate / account-number regex patterns from those same files
3. On any match, force `destination: _custom`. Add `implementation_notes: "Auto-routed to _custom/ — safeguard matched: <token>"`.

## 5. Report

Per `supertailor.agent.md` § "Report format". The report includes:

- Hygiene-pass results (what was checked, what was repaired, what was skipped).
- Strategic-pass results (count of new suggestions by destination, count of pending, declined, deferred).
- Routing summary (how many were forced from `superagent` to `_custom` by the safeguard, and what tokens triggered them).
- Quick action: for each new suggestion, ask `approve / edit / defer / decline`.

## 6. Hand-off

For approved suggestions:
- `destination: _custom` → Supertailor packages a brief and hands to the Supercoder ("Supercoder, implement st-NNN per the brief — destination `_custom`"). The Supercoder writes into `workspace/_custom/`, runs any overlay tests, reports back. Supertailor flips status to `implemented` with `implementation_notes: "<file path + summary>"` (no commit SHA — `workspace/` is gitignored).
- `destination: superagent` → Supertailor packages a brief and hands to the Supercoder ("Supercoder, implement st-NNN per the brief"). The Supercoder re-runs the safeguard, implements into `superagent/`, runs `pytest`, commits, reports back. Supertailor flips status to `implemented` with the commit SHA.
