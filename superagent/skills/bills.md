# Superagent bills skill

> **Pre-flight (lazy-materialization contract — `contracts/domains-and-assets.md` § 6.4a)**:
> The Add mode writes `Domains/<Domain>/info.md` § Routines and, when the
> first due date is close, `Domains/<Domain>/status.md` § Next Steps. Before
> either write, run:
>
>     uv run python -m superagent.tools.domains ensure <domain-id>
>
> Idempotent. The domain is the bill's `domain` field (`home` for utilities,
> `vehicles` for auto insurance, `health` for medical bills, ...).

## 1. Branch on intent

### List

User asked "what's due", "show bills", "next bill":

1. Read `_memory/bills.yaml`.
2. Recompute `next_due` for each row (handle late-paid skipped cycles).
3. Filter `status: active`.
4. Group:
   - **Overdue** (`next_due < today` AND no `history` entry for the current cycle).
   - **Due today**.
   - **Due in 1–7 days**.
   - **Due in 8–30 days**.
5. Within each group, sort by `next_due` ascending.
6. Format: `{name} {amount} {currency} — {next_due} ({auto-pay|manual})`.

If `--upcoming-only` requested, skip overdue. If `--domain <slug>`, filter accordingly.

### Mark-paid

User asked "mark <bill> paid", "I just paid <bill>":

1. Resolve bill by id or fuzzy match on name. Confirm if multiple match.
2. Ask for / infer payment date (default: today), amount paid (default: `amount`), confirmation number, source ("manual" or ingestor name), and **funding account** (default: `bills.yaml.<bill>.pay_from_account` when set; otherwise ask). If a finance ingestor is enabled, run the reconciler first (`uv run python -m superagent.tools.reconcile_transactions --days 30 --json`) and, when `bills_matched[]` holds this bill, offer its `matched_txn` (date / amount / payee) as the default answer before asking the user to type one.
3. **Capture the confirmation artifact per `contracts/payment-confirmations.md`** — save the receipt / PDF / email / screenshot to the right `Sources/<Domain>/` (or `Projects/<project>/Resources/`) folder before writing the history row, so the next steps can record `confirmation_ref`.
4. Append to `bills.yaml.<bill>.history[]`:

   ```yaml
   - date: <payment-date>
     amount: <amount paid>
     confirmation: "<conf>"
     confirmation_ref: "<workspace-relative-path-to-saved-artifact>"
     source: "<source>"
     notes: ""
   ```
5. **Mirror to the funding account** per `contracts/payment-confirmations.md § 4 step 3a`. Append to `_memory/accounts-index.yaml.<account-id>.transactions[]`:

   ```yaml
   - id: "txn-<YYYYMMDD>-<NNN>"
     timestamp: <payment-date or full ISO datetime when known>
     direction: "out"
     amount: <amount paid>
     currency: "<currency, default USD>"
     counterparty: "<bill payee>"
     purpose: "<bill name> payment"
     channel: "<ach | card_debit | check | ...>"
     confirmation: "<conf>"
     confirmation_ref: "<same path as the bill-history row>"
     status: "pending"
     related_project: <project slug or null>
     related_bill: "<bill-id>"
     related_asset: []
     related_entities: ["bill:<bill-id>"]
     provenance:
       source: "<source>"
       at: <now>
     notes: ""
   ```

   Bump `accounts-index.yaml.<account-id>.last_updated`. Skip step 5 only when the bill has no funding account on file (cash, money order, etc.); record the reason in step 4's `notes`.
6. Recompute `next_due` from cadence + due_day relative to the payment date.
7. Update `bills.yaml.<bill>.last_updated`.

### Reconcile (`bills reconcile`)

User asked to reconcile recently-ingested transactions against open bills:

1. Requires a finance ingestor with a populated ledger — `_memory/transactions.yaml` (SimpleFin is the canonical, shipped source; Plaid / Monarch / YNAB / CSV write to the same file). Do NOT hand-roll the matching; run the shared reconciler (the same tool `weekly-review` § 2 runs on a 7-day window):

   ```bash
   uv run python -m superagent.tools.reconcile_transactions --days 30 --json
   ```

   The tool is read-only (it matches by payee, ±10% amount, ±5-day window against each bill's expected due dates) and emits `bills_matched[]`, `bills_missed[]`, `recurring_candidates[]` plus `totals`.
2. For each `bills_matched[]` row whose `(matched_txn.date, matched_txn.amount)` is not already in `bills.yaml.<bill_id>.history[]` (dedup on that tuple or on `confirmation`):
   - Append a history row per the mark-paid step 4 shape with `source: "simplefin-reconcile"` (or `<ingestor>-reconcile`), `confirmation: <matched_txn.external_id>`, `confirmation_ref: null` (no artifact to file — the ledger row is the evidence).
   - Mirror to the funding account per mark-paid step 5 (`accounts-index.yaml.<pay_from>.transactions[]`), skipping when the ledger already carries the same `external_id`.
   - Recompute `next_due` and bump `last_updated` as in mark-paid steps 6–7.
3. Surface:
   - **Auto-matched**: count + bill names (from `bills_matched[]`).
   - **Bills due in the window with NO matching transaction**: `bills_missed[]` — these may have been missed.
   - **Recurring charges matching no bill / subscription**: `recurring_candidates[]` — candidates to register via the Add mode below (or the `subscriptions` Add mode), or to flag as one-shot.
4. Record the run marker (step 2 below) so "when did bills last reconcile against the ledger" is answerable by grep — the tool itself writes nothing.

### Add

User asked to add a bill ("add a bill", "new recurring bill", "I have a new <utility / insurance / loan> bill"), or accepted a `recurring_candidates[]` hit from Reconcile:

1. **Collect the bill's data** (ask only for what the trigger did not already supply):
   - **Name** (e.g. "PG&E electric", "Geico auto insurance", "Wells Fargo mortgage").
   - **Payee** (e.g. "Pacific Gas & Electric").
   - **Account** (id from `accounts-index.yaml`; the utility / provider account; optional — null if untracked).
   - **Pay-from account** (id from `accounts-index.yaml`; the bank / card that pays it).
   - **Amount** (numeric — for variable bills, the last known amount).
   - **Amount kind**: fixed | variable | usage-based.
   - **Currency** (default from config).
   - **Cadence**: monthly | quarterly | semi-annual | annual | one-shot | weekly | bi-weekly | semi-monthly | bi-monthly | irregular.
   - **Due day** (e.g. 15 = the 15th; for weekly, day-of-week 1-7; for one-shot, leave null).
   - **Auto-pay**: true / false.
   - **Grace period** (days late before urgent; default 0).
   - **Late fee** (numeric — for monthly-review surfacing).
   - **URL** (where to pay manually).
   - **Domain** (e.g. `home` for utilities; `vehicles` for auto insurance; `health` for medical bills).
   - **Asset** (id from `assets-index.yaml`; for asset-linked bills like vehicle insurance).
   - **Notes** — rate plan, contract end, promo expiration.

   Auto-derive **id** = `bill-<slug>` (e.g. `bill-pge-electric`). Before appending, grep `_memory/bills.yaml` for the same id or the same `(payee, cadence)` pair; if a row exists, offer Update instead of adding a duplicate.
2. **Compute `next_due`** — if `cadence` and `due_day` are set, compute the next occurrence after today. Otherwise leave null and surface a warning.
3. **Append the bill row** to `_memory/bills.yaml.bills[]` (shape per `templates/memory/bills.yaml`; provenance per `contracts/provenance.md`):

   ```yaml
   - id: "<id>"
     name: "<Name>"
     payee: "<Payee>"
     account: <account-id or null>
     pay_from_account: <account-id or null>
     amount: <amount>
     amount_kind: "<kind>"
     currency: "<currency>"
     cadence: "<cadence>"
     due_day: <day>
     next_due: <computed>
     auto_pay: <bool>
     grace_period_days: <n>
     late_fee: <amount or null>
     url: "<url>"
     domain: "<domain>"
     asset: <asset-id or null>
     tags: []
     notes: "<notes>"
     history: []
     status: "active"
     provenance:
       source: "user"            # "bills" with source_id: "<matched_txn.external_id>" when taken from a reconcile candidate
       at: <now>
     created: <now>
     last_updated: <now>
   ```
4. **Cross-link the account** — if `pay_from_account` is set, append the bill id to `accounts-index.yaml.<acct>.linked_bills[]`.
5. **Update domain files** (after the pre-flight `domains ensure`):
   - `Domains/<Domain>/info.md` § Routines — add the bullet "Pay <Name> {cadence} on day {due_day}".
   - If `next_due` is within 7 days, also add a bullet to `Domains/<Domain>/status.md` § Next Steps.
6. **World graph** (`contracts/world-graph.md` § 3 — write only edges `rebuild` derives): `tools/world.py.ensure_node` for `bill:<slug>`; `ensure_edge` `scoped` → `domain:<domain>` (from the row's `domain`), `pay_from` → `account:<pay_from_account>` (and → `account:<account>` when that differs), and `related_asset` → `asset:<asset>` when set. A skipped call is repaired by the next `world rebuild`.
7. **Domain reflection** (`contracts/domain-reflection.md`): `uv run python -m superagent.tools.render_domain --domain finances` (the `recurring-commitments` block reads `bills.yaml`), plus `--domain <domain>` when the bill's domain differs.
8. **Confirm**:

   ```
   Added bill "<Name>" (id: <id>) — <amount> <currency> {cadence}.
   Next due: <date>.
   Auto-pay: <yes/no>.
   ```

## 2. Sync downstream

After any add / mark-paid / update / reconcile:
- Update relevant `Domains/<Domain>/status.md` § Next Steps.
- Append to `interaction-log.yaml`. For a reconcile run this row IS the run marker (the reconciler is a pure report tool and `ingestion-log.yaml` is reserved for ingestors per `contracts/ingestion.md`):

  ```yaml
  - id: "<ilog-YYYY-MM-DD-NNN via uv run python -m superagent.tools.next_id --kind ilog --file _memory/interaction-log.yaml>"
    ts: "<now — ISO 8601 datetime with offset>"
    skill: "bills"
    action: "reconcile_transactions"
    summary: "bills reconcile --days 30: <matched> matched, <missed> missed, <candidates> recurring candidates; <appended> history rows appended."
    related_domain: finances
    related_project: null
    related_asset: null
    related_account: null
    action_items: [<bill ids appended>]
    ingestion_log_ref: null
  ```

  For the other intents use the same canonical shape (`contracts/events-stream.md` § "Canonical row shape"; never the legacy `timestamp` / `type` / `subject` fields) with `action: "add_bill"` (summary "Added bill <Name> (<amount> {cadence}, next due <date>).", `related_domain: <domain>`, `related_account: <pay_from_account>`), `"mark_bill_paid"`, `"list_bills"`, or `"update_bill"`.
- If a P0 task was auto-created by daily-update for an overdue bill that's now paid, mark that task `done`.
