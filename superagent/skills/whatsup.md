# Superagent whatsup skill

Resolve paths via `_memory/config.yaml` (`workspace_path`). Read / write `_memory/` under that root.

Run the **MCP / CLI Preflight Protocol** (`contracts/mcp-preflight.md`) for any sources this skill might touch (none required; sources are only consulted opportunistically for live state).

> **Pre-flight (email-capture contract — `contracts/email-capture.md`)**:
> If this skill ends up reading any email (rare — `whatsup` summarizes
> already-captured signal, not raw inboxes), use
> `superagent.tools.email.archive.find_by_query(...)` first and capture
> any live Gmail MCP read through `archive.capture_inbound(...)`.
> Never bulk-fetch.

## 1. Establish the time baseline

Open `_memory/context.yaml` and read `last_check`. If missing or null, treat baseline as **start of today** in the user's local timezone and state that assumption.

## 2. Bills due (next 7 days + overdue)

Read `_memory/bills.yaml`:

- Compute `next_due` for any row where `next_due` is null (use `cadence` + `due_day` + `history[-1]`).
- Filter to rows with `status: active` and `next_due <= today + 7 days`.
- Split into:
  - **Overdue** (`next_due < today` AND not in `history` for the current cycle).
  - **Due today**.
  - **Due in 1–7 days**.

For each, format: `{name} {amount currency} — {next_due} ({manual / auto-pay})`.

## 3. Today's appointments

Read `_memory/appointments.yaml`:

- Filter `status: scheduled` AND `start` is on today (local).
- For each: `HH:MM — {title} with {provider} ({location})`.
- Flag any with `prep_done: false` and `prep_notes` non-empty.

Also list the **next 2** upcoming appointments after today (date + title) for context.

## 4. Important dates (today / tomorrow / next 7)

Read `_memory/important-dates.yaml`:

- Recompute `next_occurrence` for each row.
- **Today**: `{title} ({recurrence_year_count} years)`.
- **Tomorrow**: same.
- **Next 7 days**: list (with date prefix).

If a date in the gift-shopping window has empty `gift_log` for this year, surface the prompt: *"Want a gift idea for {title}?"* (offers to draft via `important-dates suggest-gift <id>`).

## 5. Tasks (P0 + overdue)

Read `_memory/todo.yaml`:

- **P0 open**: list (id, title, due, related_domain).
- **P1 open AND overdue** (`due_date < today`).
- **P1 open AND due in next 3 days**.

If overdue count > 0, end with:

> **<N> overdue tasks** — run `todo triage` to force a decision on each.

Echo the same pointer line into this run's `interaction-log.yaml` row `action_items` (step 9) so the pointer is auditable by grep.

## 6. Watchlist alerts (read-only — never checks)

`whatsup` is the light tier: it **never runs** `watchlist check` and makes no network calls. It reads what the last check wrote (`contracts/watchlist.md`).

1. From the `_memory/context.yaml.alerts` strings already loaded in step 1, take those that start with `[watch:` — the form is `[watch:<id>] <ISO ts>: <summary>`, one live alert per watcher. The ISO timestamp between `]` and the first `:` is the detect time — label the age in words ("3 days ago", "this morning"); never present a stale delta as current.
2. Tail-read `_memory/ingestion-log.yaml` (recent slice only) for harvest rows with `started_at >= last_check`: new `transactions` / `bills` / `appointments` rows worth a line, plus any per-source `errors` not yet acknowledged.
3. If the newest watchlist `ts` is older than 24 hours (or no check has ever run), end the block with: *"Watchlist last checked <age> — run `daily-update` to refresh."*

Surface anything that warrants attention, max 5 items.

## 7. Open signals (Supertailor + Superagent)

Read `_memory/action-signals.yaml`:

- T = count of `target: tailor` AND `status: captured`.
- S = count of `target: superagent` AND `status: captured`.

If T > 0 AND last `supertailor-review` > 30 days ago: surface `Consider: supertailor-review — N unprocessed framework signals.`

If S > 0: surface `Consider: drain pending workspace actions — N captured. Say "show pending workspace actions".`

**Overdue cadences** (single line, mirrors `daily-update` § 15): compare `config.preferences.cadences` + the `<skill>_auto` flags against `_memory/context.yaml.last_runs`. If any of weekly_review (> 7 days), monthly_review (past the 1st, last run in a prior month), or doctor (null / > 180 days, workspace older than 180 days) is overdue, surface one line: `Overdue cadences: monthly-review (due <MM-DD>), ...`. Skip silently when none are overdue.

## 8. Present summary

Output one concise opening line:

> Since your last check at **<time>**: **<X>** bills due / overdue, **<Y>** appointments today, **<Z>** important dates this week, **<N>** P0/P1 tasks overdue, **<M>** watchlist alerts (newest <age>).

Then:

- A `### Today` block with appointments + P0 tasks + bills due today + important dates today.
- A `### This week` block with bills due in 1–7 days, P1 tasks due in next 3, important dates in next 7.
- An `### Alerts` block (if step 6 had findings).
- A `### Waiting on your call` block (up to 5 items, one line each): open tasks blocked on a decision (greppable convention: task `notes` carry `blocked_on: decision`), `decisions.yaml` rows with `review_at` due, explicitly deferred questions.
- A `### Consider` block (if step 7 had nudges) — max 3 items.

Skip empty sections silently. Total output target: ≤ 30 lines.

## 9. Update context

1. Set `_memory/context.yaml.last_check` to now (ISO 8601 with TZ offset).
2. When a `context.yaml` alert's condition is resolved or superseded, MOVE it verbatim to `_memory/alerts-archive.yaml` (append a row) and delete it from `context.yaml` — never annotate resolved alerts in place. Same for `recent_activity` beyond the newest ~8 entries and for superseded `current_focus` prose.
3. Append a short canonical row to `interaction-log.yaml` (shape per `templates/memory/interaction-log.yaml`; mint the id with `uv run python -m superagent.tools.next_id --kind ilog --file <workspace>/_memory/interaction-log.yaml`):

   ```yaml
   - id: "<ilog-YYYY-MM-DD-NNN>"
     ts: <now, ISO 8601 with offset>
     skill: "whatsup"
     action: "quick_delta"
     summary: "Quick delta surfaced (X bills, Y appts, Z dates, N tasks, M alerts)."
     related_domain: null
     action_items: []   # include the step 5 overdue-triage pointer and any step 7 nudge lines emitted this run
   ```
