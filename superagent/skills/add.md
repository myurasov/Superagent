# Superagent add skill

> **Pre-flight (lazy-materialization contract — `contracts/domains-and-assets.md` § 6.4a)**:
> This skill writes `Domains/<owning-domain>/history.md` (every kind),
> `Domains/<owning-domain>/status.md` § Next Steps (asset, when seeding
> maintenance) and `Domains/<owning-domain>/Resources/<asset-slug>/` (asset
> working files). Before any of these, run:
>
>     uv run python -m superagent.tools.domains ensure <owning-domain>
>
> Idempotent. The owning domain is the `domain` field on the new row
> (`finances` for most accounts; `vehicles` / `home` / `assets` / `hobbies`
> for assets; per the kind table in § 3 for documents).

## 1. Route — is this the right skill?

Resolve what the user is adding before collecting anything:

| The user is adding ... | Skill |
|---|---|
| a financial / utility / subscription **account**, a physical **asset**, an important **document** record | **this skill** (§ 2 picks the kind) |
| a **bill** / **subscription** / **appointment** / **important date** | the Add mode of `bills` / `subscriptions` / `appointments` / `important-dates` |
| a **contact**, **domain**, **project** | `add-contact` / `add-domain` / `add-project` |
| a **file** for the library (`Sources/`) | `add-source` — see the boundary below |
| something external to **watch for change** (a page, a portal, a feed) | `watch` |

**`add` ↔ `add-source` boundary (documents).** `add-source` owns the *file*: whenever a document's bytes enter the library it places them under `Sources/` (user-defined layout, `contracts/sources.md` § 15.1), writes the optional `<doc>.<ext>.meta.md` sidecar, refreshes `_memory/sources-index.yaml` and catalogues the row in the domain's / project's `sources.md`. `add` kind `document` owns the *record*: a `documents-index.yaml` row carrying the structured metadata (`kind`, `for_member`, `issuer`, last-4 `number`, `vault_ref`, `issued_date`, `expires_at`, `physical_location`) that drives expiration surfacing — whether or not a digitized file exists (a physical-only passport still gets a row). When both apply (a scanned passport, a warranty PDF), run `add-source` for the file first, then this skill with `path` pointing at the placed file; this skill never moves or copies a file itself (§ 7 Document step 2). A routine receipt or payment confirmation is neither: it follows `contracts/payment-confirmations.md`, which files the artifact via `add-source` and calls this skill only for long-lived receipts that warrant a `documents-index.yaml` row.

## 2. Resolve the kind

`account` | `asset` | `document`. Take it from the trigger when unambiguous ("add an account", "I bought a new car", "track this passport"); otherwise ask with `AskQuestion` (single-select, the three kinds plus "something else" → back to § 1).

## 3. Collect the fields (per kind)

Ask only for what the trigger did not already supply. Use `AskQuestion` for single-select fields (the kind sub-type), inline free text for the rest; one batch where reasonable, otherwise short follow-ups.

### Account

- **Name** (e.g. "Chase Total Checking", "Fidelity 401(k)", "PG&E electric").
- **Institution** (bank / brokerage / utility / subscription provider).
- **Kind** (single-select): checking · savings · credit_card · brokerage · retirement (401k / 403b / IRA / Roth / pension) · loan · mortgage · utility · insurance · subscription · membership · wallet (Apple Pay / Google Pay reference) · hsa / fsa / hsa_invest · other.
- **Number last 4** (for matching transactions). NEVER ask for the full number.
- **Vault ref** — where the full credential lives. Ask for the password-manager item identifier (e.g. `1Password://Personal/chase-checking`, `keychain:bofa-savings`). Optional but encouraged.
- **URL** (login URL).
- **Primary holder** — `self` | `joint` | `spouse` | `child:<name>` | other.
- **Currency** (default `config.preferences.money.currency`).
- **Opened date** (ISO 8601 date or null).
- **Beneficiaries** (relevant for retirement / life insurance — list of names).
- **Low-balance threshold** (for checking / savings; defaults to `config.preferences.money.low_balance_default`).
- **Domain** — `finances` unless the user says otherwise (`business` for a business account).
- **Notes** — APR, terms, special instructions.

Auto-derive **id** = `<kind>-<institution-short>-<last4 or other discriminator>` (e.g. `checking-chase-1234`, `401k-fidelity`, `electric-pge`).

### Asset

- **Name** (e.g. "Blue Camry", "Living-room Samsung TV", "Mom's pearl necklace").
- **Kind**: vehicle | appliance | electronics | jewelry | instrument | tool | collectible | furniture | art | other.
- **Sub-kind** if vehicle: car | motorcycle | bicycle | boat | RV | truck | scooter | other.
- **Domain**: which domain owns this? (default heuristic: vehicle → `vehicles`; appliance → `home`; jewelry → `home` or `family`; tool → `home` or `hobbies`; instrument → `hobbies`; other → ask).
- **Make / Model / Year**: free text.
- **Color** (if useful for identification).
- **Serial** (electronics / appliances) OR **VIN** (vehicles).
- **Purchase date** (ISO 8601 date).
- **Purchase price** (numeric).
- **Warranty expiration** (date or null).
- **Insurance** (one line: carrier + policy ref).
- **Location** (where it lives — e.g. "garage", "kitchen", "safe deposit box").
- **Notes** — anything else worth remembering.

Auto-derive **slug** = `<kind>-<color-or-make>-<short-model>-<year>` lowercased, hyphenated, e.g. `car-blue-camry-2018`. Confirm. A financial holding (stock, ETF, crypto, cash position) uses the same row with the template's financial fields (`ticker`, `units`, `cost_basis`, `held_in_account` → the `account:` handle it sits in) instead of the physical ones.

### Document

- **Title** (e.g. "Passport — self", "Auto insurance — Camry").
- **Kind** (single-select): passport | drivers_license | state_id | social_security | birth_certificate | marriage_certificate | divorce_decree | death_certificate | naturalization | green_card | visa | deed | title | mortgage_doc | lease | will | trust | power_of_attorney | living_will | medical_directive | insurance_policy | warranty | receipt | tax_return | w2 | 1099 | k1 | property_tax | school_record | medical_record | vaccine_record | prescription | diploma | certification | contract | nda | other.
- **For member** — "self" | name | "household".
- **Issuer** (e.g. "U.S. Department of State", "California DMV", "Geico").
- **Number** — last 4 digits ONLY for sensitive kinds (passport / SSN / DL); full number ok for non-sensitive (warranty / receipt).
- **Vault ref** — where the full number / scan lives (e.g. "1Password://Personal/passport-self").
- **Issued date** (ISO 8601).
- **Expires at** (ISO 8601 — drives expiration surfacing).
- **Path** — workspace-relative path to the digitized file under `Sources/` (null when physical-only; if the file is not in the library yet, § 7 Document step 2 offers `add-source`).
- **Physical location** — where the original is stored (e.g. "fireproof safe", "safe deposit box at Wells Fargo Hayward", "office filing cabinet drawer 2", "with parent in <city>").
- **Domain** — auto-suggest based on `kind`:
  - passport / drivers_license / state_id / social_security / birth_certificate / marriage_certificate → `family` (or `self`)
  - deed / mortgage_doc / lease → `home`
  - title → `vehicles`
  - will / trust / power_of_attorney / living_will / medical_directive → `family` (or `self`)
  - insurance_policy → `finances`
  - warranty → the asset's domain
  - tax_return / w2 / 1099 / k1 / property_tax → `finances`
  - school_record / diploma → `family` or `career`
  - medical_record / vaccine_record / prescription → `health`
  - certification → `career`
- **Notes** — anything else (e.g. "include for international travel").

Auto-derive **id** = `doc-<kind>-<for_member>` (e.g. `doc-passport-self`, `doc-insurance-camry`).

## 4. Check for duplicates

Grep the target index before appending — never load it whole:

- **account**: `_memory/accounts-index.yaml.accounts[]` by `id` and by `(institution, kind, number_last4)`.
- **asset**: `_memory/assets-index.yaml.assets[]` by `id` and by `(make, model, serial | vin)`.
- **document**: `_memory/documents-index.yaml.documents[]` by `id` and by `(kind, for_member)`.

On a hit, confirm: update the existing row, or add a second one (e.g. a renewed passport → new row, old row `status: replaced`).

## 6. Sensitive handling

Per `contracts/sensitive-tier.md` and `contracts/visibility.md`:

- **Never capture a full account, passport, SSN or licence number.** Last 4 only; the full credential / number / scan lives in the user's password manager and is referenced by `vault_ref`. If the user pastes a full number, store the last 4 and say so.
- `accounts-index.yaml` is a flagged file (`config.preferences.sensitive.auto_route_files`): write it at `_memory/accounts-index.yaml` and follow whatever symlink the user placed there — never assume it lives under `_memory/sensitive/`.
- Set `sensitive: true` on the row for vital records (passport, social_security, birth / marriage certificate, will, trust, medical_directive, medical_record) and for any account the user flags — it opts the single row into outbound redaction regardless of file.
- Mirror the flag into the `add-source` call when the same turn files the document (`Sensitive?` → true for medical, legal, accounts).

## 7. Kind-specific follow-through

### Account

1. **Cross-link.** Ask:
   - **"Are any existing bills paid from this account?"** — for each yes, append to `linked_bills` here AND set `bills.yaml.<bill>.pay_from_account = <account-id>`.
   - **"Are any existing subscriptions charged to this account?"** — same for `linked_subs` / `subscriptions.yaml.<sub>.pay_from_account`.
2. **Optional — wire to the finance harvest.** If a `simplefin` watcher is registered in `Sources/Watchlist/` (`uv run python -m superagent.tools.watchlist list`):

   > "Want to link this account to **SimpleFIN** so its transactions get harvested into it? (yes / later / never)"

   On `yes`: set `accounts-index.yaml.<acct>.simplefin_account_id` to the account's SimpleFIN UUID — `uv run python -m superagent.tools.watchlist harvest --id simplefin --dry-run` lists the feed's accounts without writing anything. The reconciler uses that field to join harvested transactions to bills' `pay_from_account`.

   No `simplefin` watcher yet → point at `superagent/docs/data-sources.md#simplefin` and the `watch` skill (`enable simplefin`).

### Asset

1. **Per-asset sub-folders (optional).** If the user has receipts / scans / titles / warranty PDFs to file (vault-grade documents):
   - **Source documents** — invoke `add-source --to-domain <Domain> --asset <asset-slug>` for each. That skill SUGGESTS a path like `workspace/Sources/<category>/<asset-slug>/` (the user can override) and adds a row to `Domains/<Domain>/sources.md`; the asset row's `receipts[]` / `photos[]` get the path via its § 4c cross-link. Source documents NEVER go under `Domains/<X>/` directly.
   - **Working files** — for context photos (the serial-number sticker, the leak that started this), per-asset `workspace/Domains/<Domain>/Resources/<asset-slug>/` is the right home. Created lazily.

   Do NOT create either folder if there's nothing to put in it.

   | motorcycle | oil change | 180 (3000 mi) |
   | motorcycle | chain lube | 30 |
   | motorcycle | registration renewal | 365 |
   | bicycle | tune-up | 365 (1000 mi) |
   | HVAC | filter change | 90 |
   | HVAC | service | 365 (spring) |
   | furnace | service | 365 (fall) |
   | water heater | drain | 365 |
   | water heater | anode rod check | 1095 (3 yr) |
   | refrigerator | water filter | 180 |
   | refrigerator | coil clean | 365 |
   | dishwasher | filter clean | 30 |
   | dishwasher | deep clean | 365 |
   | washing machine | drum clean | 30 |
   | dryer | vent clean | 365 |
   | smoke detector | battery | 365 |
   | smoke detector | replace unit | 3650 (10 yr) |

   On `yes` or `customize`: append rows to `assets-index.yaml.<asset>.maintenance[]` and compute `next_due` for each. Optionally add a P2 task to `todo.yaml` for the soonest one.
3. **Warranty expiration.** If `warranty_expires` is set, offer an `important-dates` Add (kind `expiration`) so it surfaces ahead of time.

### Document

1. **Expiration guard.** If `expires_at` is set, surface immediately:
   - < 30 days → P1 task auto-created ("Renew <Title>").
   - 30–60 days → P2 task suggested.
   - 60–90 days → just echo, no task.
2. **File the digitized document.** If the user has a scan / PDF that is not yet under `Sources/` (a fresh scan, a download, an attachment), offer:

   > "Want me to file this in the library first? I'll suggest `Sources/<category>/<filename>` — you can pick another path."

   On `yes`: hand the file to `add-source --to-domain <inferred>` (which places it, adds the row to the domain's `sources.md`, and refreshes `_memory/sources-index.yaml`), then set `documents-index.yaml.<doc>.path` to the placed `Sources/<...>` path. This skill never moves or copies the file itself (boundary in § 1).
3. **Payment receipts.** When `kind: receipt` and the receipt represents a payment (vs. a purchase warranty), the canonical capture path is `contracts/payment-confirmations.md`, NOT this skill. That contract decides destination (`Sources/<Domain>/` vs `Projects/<project>/Resources/`), cross-links to `bills.yaml` / `subscriptions.yaml` / `appointments.yaml`, and calls this skill only for long-lived receipts that warrant a `documents-index.yaml` row (taxes, large medical, property, vehicle major service). Routine bill-payment confirmations skip the `documents-index` row.

## 9. World graph

Per `contracts/world-graph.md` § 3 — write only edges `rebuild` derives, with the same kinds: `tools/world.py.ensure_node` for the new handle (`account:<id>` / `asset:<slug>` / `document:<id>`), then `ensure_edge` `scoped` → `domain:<domain>` from the row's `domain` (every kind), plus per kind:

- **account** — `pay_from` from each `bill:<id>` / `subscription:<id>` whose `pay_from_account` § 7 step 1 set (the edge runs bill → account; evidence `bills.yaml.<id>.pay_from_account`); `linked_account` → `account:<other>` for each `linked_accounts[]` row; `related_asset` → `asset:<id>` for each `linked_assets[]` entry. `linked_bills[]` / `linked_subs[]` yield no edge of their own.
- **asset** — no further edge: the bill → asset `related_asset` edges are written by the `bills` Add mode when § 7 step 2 seeds maintenance bills (`asset: <slug>` on each), and a holding's `held_in_account` is not a graph edge.
- **document** — `for_member` → `contact:<id>` only when `for_member` is a contact id (never for `self` / `household`).

A skipped call is repaired by the next `world rebuild`.
