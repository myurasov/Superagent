# Superagent events skill

Implements superagent/docs/_internal/ideas-better-structure.md item #16 + superagent/docs/_internal/perf-improvement-ideas.md MI-2. Engine: `tools/log_window.py`.

## 1. Branch on intent

### Read (default for "what happened")

User said "what happened on April 15" / "show events this week":

1. Determine window:
   - "today" -> start of today -> now.
   - "this week" -> last 7 days.
   - "this month" -> last 30 days.
   - "<date>" -> 00:00:00 to 23:59:59 of that date.
   - "between X and Y" -> explicit range.
2. Run:
   ```
   uv run python -m superagent.tools.log_window read --since <iso> --until <iso> [--kind <kind>] [--limit 200]
   ```
3. Group by `kind`. Surface: `<ts>  [<kind>] <subject>` per row.

### Append

The events stream is a DERIVED VIEW (per `contracts/events-stream.md`) — do
NOT append to partitions directly. To put something on the timeline, write it
to a source of truth instead:

- an `_memory/interaction-log.yaml` entry (agent actions, skill runs), or
- a Domain/Project `history.md` H4 entry (`#### YYYY-MM-DD — <title>`;
  an optional time / parenthetical suffix may sit between date and
  separator, e.g. `#### 2026-05-26 08:30 PT — ...`).

It materializes as an event on the next rebuild:

```
uv run python -m superagent.tools.events_derive rebuild
```

Direct appends via `tools/log_window.py append` are overwritten by the next
rebuild unless the row carries `legacy: true`; skills must not use them.

Standard event kinds (see `events.yaml` template):
- interaction, ingest_run, skill_run, status_flip
- bill_paid, task_completed, task_created
- appointment_completed, health_event, maintenance_done
- decision, important_date_marked
- source_added, source_accessed, project_milestone
- audit, capture_signal, cache_evict, ingest_failure, other

### Stats

`events stats` -- partition counts; useful after rotation or import.

```
uv run python -m superagent.tools.log_window stats
```

### Rebuild / staleness

Rebuild the derived partitions (mtime-lazy; cheap when nothing changed), or
check whether the sources have moved past the last derivation:

```
uv run python -m superagent.tools.events_derive rebuild
uv run python -m superagent.tools.events_derive check   # exit 1 = stale
```

The rebuild also refreshes `_memory/events.yaml` (the partition index over
the events/ directory).

## 2. Derivation contract

Per `contracts/events-stream.md` (revised 0.16.0): the partitions are rebuilt
wholesale by `tools/events_derive.py` from `interaction-log.yaml` + Domain/
Project `history.md` H4 entries. Rows flagged `legacy: true` are frozen
byte-verbatim; everything else regenerates on each rebuild. The former
per-write mirror toggles (`auto_mirror_history_md` /
`auto_mirror_interaction_log`) are retired — `config.preferences.events.mode`
is `derived` (or `off`).

## 3. Logging

This skill adds a single line to `interaction-log.yaml` for cadence-skill discoverability — which is itself a source of truth for the next derivation, so no separate event write is needed.
