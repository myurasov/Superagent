# Superagent world skill

Front-end to the world graph: `_memory/world.yaml`, the derived entity-relationship index defined in `contracts/world-graph.md` and maintained by `tools/world.py`. Nodes are operational handles (`<kind>:<slug>`); edges are the cross-references between entity rows. The graph is a cache of the entity files — safe to rebuild at any time, never edited by hand.

## 1. Preflight

1. Read `_memory/config.yaml` and resolve `preferences.workspace_path` (default: the `workspace/` sibling of `superagent/`). When it differs from the default, add `--workspace <path>` to every command below.
2. Do not open `_memory/world.yaml` itself — it holds hundreds of nodes and edges; every question below goes through the tool.
3. If any command prints `warn: world.yaml last rebuilt <N> days ago` on stderr, answer the question first, then offer a rebuild (§ 2c) in one line.

## 2. Branch on intent

### 2a. Related (default) — "what is connected to X", "what is linked to X"

1. Resolve `X` to a handle: `contact:dr-smith-dentist`, `project:tax-2026`, `bill:pge-electric`, `watch:simplefin`, ... The tool also accepts legacy bare ids via `tools/handles.py.parse()` (`contact-abc` → `contact:abc`); a bare slug with no known legacy prefix is looked up as written and, if unknown, reported as not found. When the user gave a display name, grep the slug in the matching index (`_memory/contacts.yaml`, `projects-index.yaml`, `bills.yaml`, ...) rather than opening the index.
2. Run

   ```
   uv run python -m superagent.tools.world related <handle> --depth 1
   ```

   Use `--depth 2` when the user says "everything" / "the whole neighbourhood" rather than "directly"; add `--json` when you need to group or filter programmatically (returns `{node, neighbors[], edges[]}`).
3. The text output is a header (`# Related to <handle> (kind: <kind>)`, a neighbour / edge count line) followed by one `  - <handle> [<kind>] — <label>` line per neighbour. Render it grouped by `kind` — one `###` per kind with a count, handles kept visible so the user can follow up:

   ```
   ## Related to contact:dr-smith-dentist (depth 1)

   ### appointment (3)
   - appointment:20260512-cleaning — 2026-05-12 cleaning
   - appointment:20251115-cleaning — 2025-11-15 cleaning
   - appointment:20250515-cleaning — 2025-05-15 cleaning

   ### domain (1)
   - domain:health — Health
   ```

4. Zero neighbours: say so, and offer § 2c — the entity may be newer than the last rebuild.

### 2b. Stats — "how big is the graph", "graph stats"

```
uv run python -m superagent.tools.world stats
```

Prints JSON: `node_total`, `edge_total`, `by_node_kind`, `by_edge_kind`, `last_rebuild`, `last_updated`. Report the totals, the largest kinds, and `last_rebuild`. Useful after a schema change or an import.

### 2c. Rebuild — "rebuild the graph", after a bulk import or a migration

```
uv run python -m superagent.tools.world rebuild
```

Walks every entity-shape file and reconstructs nodes + edges from scratch; prints `rebuilt: <N> nodes, <M> edges` followed by the stats JSON. Safe at any time. If you have earlier totals in context, mention a large drop in one sentence.

### 2d. Validate — "is the graph consistent", hygiene passes

```
uv run python -m superagent.tools.world validate
```

Prints `Graph consistent.` (exit 0), or one `warn: edge from|to unknown node: <handle>` line per dangling edge plus a count (exit 1). Warnings are informational; the fix is § 2c. `supertailor-review` runs `validate` in its hygiene pass; `doctor` checks graph freshness and offers `rebuild`.

## 3. Watchers in the graph

Every watcher in `Sources/Watchlist/<name>.ref.md` (per `contracts/watchlist.md`) is a `watch:<id>` node — `id` = filename stem lowercased, `kind: watch` — with an `indexed_as` edge to its `source:<row id>` node. The ref's `related_domain` / `related_project` / `related_asset` / `related_account` fields become edges from `watch:<id>` (`scoped`, `related_asset`, `pay_from`), so `related project:<slug>` lists that project's watchers and `related watch:<id>` shows what a watcher feeds. The `watch` skill keeps these edges current; a rebuild re-derives them from `sources-index.yaml`.

## 4. Keeping the graph current

Per `contracts/world-graph.md` § 4, a skill that creates an entity row calls `tools/world.py.ensure_node(...)` and `ensure_edge(...)` in the same transaction. This skill only queries, validates, and rebuilds; when a neighbour is missing, run § 2c rather than patching `world.yaml`.
