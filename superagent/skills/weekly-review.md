# Superagent weekly-review skill

> **Bulk reads** (`rules/subagents.md`): any lookup expected to pull more than
> ~20k tokens of raw tool results (~10k once the economy level resolves to `full`;
> multi-entity sweeps, whole email thread trees, long histories or archives) runs
> in a subagent (`Explore` read-only / `general-purpose` if it must write) that
> returns only the synthesis — named facts, quotes, `file:line` pointers — never
> raw dumps into the main transcript.


Compute a **trailing 7-day window** ending today (local).

## 1. Run weekly-cadence ingestors

For sources with `schedule: weekly` in `data-sources.yaml`, run their ingestors (per the ingestion contract). Collect counts.

If `simplefin` is enabled (the canonical finance ingestor), run it explicitly:

```bash
uv run python -m superagent.tools.ingest.simplefin
```

## 2. Bookkeeper pass

If at least one finance ingestor is enabled and the recent transactions are mirrored:

1. Read transactions from `_memory/transactions.yaml` (SimpleFin / Plaid / Monarch / CSV all write here).
2. Run the reconciler for a 7-day window — it cross-references transactions against `bills.yaml` (matched / missed) and surfaces recurring-charge candidates not yet tracked in `bills.yaml` / `subscriptions.yaml`:

   ```bash
   uv run python -m superagent.tools.reconcile_transactions --days 7
   # or `--json` for structured consumption
   ```

3. Surface in the review under headings: **Bills missed**, **Bills paid**, **Recurring-charge candidates** (audit prompt: "Add to bills.yaml or subscriptions.yaml?").
4. Independent of the reconciler, total `inflows` and `outflows` for the trailing 7 days; group outflows by `category`; flag categories > 1.5× their 4-week trailing average. When totalling, skip rows flagged `stale_pending: true` or carrying `superseded_by` — they are pending twins of a posted transaction and would double-count.

If no finance ingestor is enabled, skip with a one-line note: *"Bookkeeper pass skipped — no finance ingestor configured. See `docs/data-sources.md#finance` to enable."*

## 3. Coach pass

If at least one fitness / health ingestor is enabled:

1. Workouts logged this week (count + total minutes + total distance if applicable).
2. Sleep average (hours, score) over last 7 nights.
3. Weight trend (delta vs 4 weeks ago).
4. Personal-signal events captured this week (count by category).
5. Streak status against any active goal in `Domains/Hobbies/status.md`.

If no fitness ingestor is enabled, surface manual reflection prompt:

> "Coach pass: no fitness ingestor configured. Want to log this week's workouts manually? (`Hobbies` domain)"

## 4. Concierge pass — coming up

Read `_memory/appointments.yaml`, `_memory/important-dates.yaml`, `_memory/documents-index.yaml`:

- Appointments in next 14 days.
- Important dates in next 30 days.
- Documents expiring in next 60 days.

Group by domain.

## 4b. Project rollup

Read `_memory/projects-index.yaml.projects[]`:

For each project with `status: active`:
- **Burn-down**: render `{checked}/{total} success criteria — {days} days to target` (when criteria ≥ 5).
- **This week's progress**: count of tasks completed for this project in last 7 days; H4 entries appended to project's `history.md` in last 7 days.
- **Stalled?**: if NO entry in the project's `history.md` AND no completed tasks in last 14 days → flag as `stalled`. Suggest pause or push.
- **Drift**: index-status-vs-activity mismatches (e.g. `active` in the index but a silent history) are flagged per doctor's project-drift check — cite it, don't re-derive here.

Also list:
- **Projects in `planning`** — chartered but not yet active. Prompt: "ready to flip these to active?".
- **Projects with target_date in next 30 days** — will dominate the next monthly cycle.
- **Recently completed projects** (last 7 days) — surface lessons-learned prompt if not already captured.

## 5. Quartermaster pass — maintenance

Read `_memory/assets-index.yaml`:

- Maintenance items due in next 30 days.
- Warranties expiring in next 60 days.

Group by domain.

## 5b. Decisions this week

Read `_memory/decisions.yaml` (tail-read; it is time-shape): list decisions
with `ts` in this week's window, one line each (`contracts/decisions.md`).
Skip the section silently when there are none.

## 5c. Stale Outbox drafts

Per `contracts/outbox-lifecycle.md` § "Stale-drafts surfacing". Read
`config.preferences.outbox.drafts_stale_days` (default **14** when the key is
absent), then tail-read `_memory/outbox-log.yaml.artifacts[]` (time-shape):

- Keep rows with `stage: drafts` whose `last_updated` (fall back to the newest
  `stage_history[].ts`) is older than `drafts_stale_days`.
- For each, check that `path` still exists on disk. Existing → list as
  `<path> — drafts since <date> (<N> days)`. Missing → list separately as an
  **untracked deletion** and offer to mark the row `stage: discarded`.

Skip the section silently when nothing qualifies (or the log is absent).

## 6. Tasks

Read `_memory/todo.yaml`:

- **Done this week** (count + list of titles).
- **Slipped** (open tasks with `due_date` in this week's window that aren't done).
- **New tasks created this week** (count by `source`).
- **Coming due in next 7 days** (P0 + P1).

## 7. Reflection prompt

Ask the user (one prompt, accept skip):

> "Two questions for the log — type a sentence each, or 'skip':
>
>   1. **What worked well this week?**
>   2. **What do you want to do differently next week?**"

Capture both answers as a single H4 entry in `Domains/Self/history.md`:

```markdown
#### <YYYY-MM-DD> — Weekly review

**Worked well**: <answer 1>

**Differently next week**: <answer 2>

---
```

If either answer hints at a personal signal (heuristic: contains words like "should", "need to", "want to be", "next time"), capture as a `personal-signals.yaml` row (per `contracts/capture.md` § 7.1) and tag it inline.

```
# Weekly review — week of <Mon DD> through <Sun DD>

## Bookkeeper
- Inflows: <total>
- Outflows: <total>
- Top 3 categories: <list with $>
- Outliers: <flagged categories>
- New recurring charge candidates: <list with "add to bills/subs?">
- Bills paid: <count>; bills missed: <count>

## Coach
- Workouts: <count> (<minutes> min, <distance>)
- Sleep avg: <hours>h, score <score>
- Weight trend: <delta>
- Streak status: <one line>

## Concierge — coming up
- Appointments in next 14 days: <list>
- Important dates in next 30 days: <list>
- Documents expiring in next 60 days: <list>

## Quartermaster — maintenance
- Maintenance due in next 30 days: <list>
- Warranties expiring in next 60 days: <list>

## Tasks
- Done this week: <count>
- Slipped: <count + list>
- New: <count by source>
- Due in next 7: <list>

## Outbox — stale drafts (if any)
- <path> — drafts since <date> (<N> days)

## Reflection
**Worked well**: <answer 1>
**Differently next week**: <answer 2>
```

On request ("printable copy", "as a pdf"), export the composed review as a
PDF via the `report` skill (destination `Outbox/reports/`).

**Discovery nudge** (max one per run; deterministic, not aspirational). Evaluate the two checks below in order and append ONE line for the first that fires:

- (a) **follow-up**: `todo.yaml` overdue count >= 3 AND `interaction-log.yaml` has no `subject: follow-up` or `subject: triage-overdue` row in the last 30 days → `Consider: follow-up — N overdue tasks and no follow-up pass in 30 days.`
- (b) **expenses**: `data-sources.yaml` has a finance source (`simplefin` or another `kind: finance` row) with `last_ingest` within 7 days AND `interaction-log.yaml` has no `subject: expenses` row ever → `Consider: expenses — bank transactions are flowing but spending has never been reviewed.`

Record the emitted nudge line in this run's `interaction-log.yaml` row `action_items` (step 9). Record declines in `model-context.yaml` communication notes and never re-nudge a declined skill — the interaction-log echo is what makes that rule auditable.

## 8b. Derived views rebuild

The world graph (`_memory/world.yaml`) and the events stream
(`_memory/events/<YYYY-Qn>.yaml`, per `contracts/events-stream.md`) are both
derived data — cheap to rebuild. Run both every review so they never go stale:

```bash
uv run python -m superagent.tools.world rebuild
uv run python -m superagent.tools.events_derive rebuild
```

## 9. Update memory

2. Append entry to `_memory/interaction-log.yaml` (its `action_items` carries any discovery-nudge line from step 8 and the stale-draft paths from step 5c).
3. If reflection captured a personal signal, append to `_memory/personal-signals.yaml`.
4. The `Domains/Self/history.md` H4 entry is already written in step 7.
