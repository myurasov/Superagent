# Report skill — printable reports (HTML source, PDF render)

Produce a shareable, printable document: the agent authors one
self-contained HTML file in the framework document style, and
`tools/render_report.py` prints it to a US-Letter PDF. The HTML is the
source of truth (browser-previewable, hand-tunable); the PDF is always a
derived artifact, re-rendered after any edit — never hand-edited.

## 1. Decide destination

Pick by the artifact's home, then create/verify the folder:

- **Shareable / printable for someone else** (contractor brief, packet,
  exported summary) → `workspace/Outbox/reports/`. Per
  `contracts/outbox-lifecycle.md` § "Lazy sub-directory creation", first run
  `uv run python -m superagent.tools.outbox ensure reports`, and append a row
  to `_memory/outbox-log.yaml.artifacts[]` when the PDF lands.
- **Domain- or project-scoped working report** →
  `workspace/Domains/<domain>/Resources/` or
  `workspace/Projects/<slug>/Resources/` (create the `Resources/` folder
  lazily if missing).
- **Ad-hoc task deliverable** → the task's own
  `tasks/<YYYY>/<MM>/<YYYY-MM-DD>-<slug>/` folder.

Name the file `<YYYY-MM-DD>_<kebab-slug>.html` (render date, underscore
separator per `rules/file-naming.md`); the PDF renders beside it with the
same stem.

## 2. Author the HTML

Start from `superagent/templates/reports/report.html` (copy it to the
destination and rename). Structure, in order, inside
`<body class="viz-root"><main>`:

1. **H1**: `<Title><br><span class="h1-subtitle"><Document Type> — Rev. N</span>`.
   Title Case. Bump Rev. N on every content update; the filename never
   changes. The renderer parses the H1 + subtitle for the pages-2+ running
   header, so the rev shows on every page.
2. **`.sub` paragraph** — provenance one-liner: when prepared, what data it
   draws on (and as-of dates), what question it answers.
3. **Inline TOC** — `.toc` div with `--toc-rows: <ceil(items/columns)>` and a
   `.toc-list` OL of anchors to the `h2` ids.
4. **Headline table** (`table.headline`) — Metric | Value | Note rows; never
   stat tiles or boxes.
5. **Sections** — `<section><h2 id="s-...">`; H2s carry NO hardcoded numbers
   (a CSS counter numbers them). **The last section is always Conclusion**:
   the verdict in plain sentences, closing with one sentence that summarizes
   the result and the recommendation.
6. **`.foot` paragraph** — sources line. No "Prepared by" in the body; the
   renderer owns all page furniture.

Content rules:

- Tables: cells center by default; prose/row-label cells get `class="lft"`;
  header cells get explicit `style="width:N%"` hints. Header rows live in
  `<thead>`. Tables that may span pages get `class="split"`; all others move
  whole. `class="hl"` on one `<tr>` marks the single attention row.
- **Bold sparingly and only for good news** (savings found, "on track",
  "covered"); never bold negative or neutral outcomes.
- Every technical or domain term gets a ~10–15-word plain-word parenthetical
  at first use. Numbers are measured, not extrapolated; `.foot` states
  sources. Timestamps labeled with the user's timezone.
- Sensitive data follows `contracts/sensitive-tier.md`: reports built from
  `health-records.yaml` / `accounts-index.yaml` get the "do not paste into an
  untrusted assistant" banner, and account numbers appear masked (last 4).
- Interactive charts are for the HTML only (wrap in `.chart-block`, hide it
  under `@media print` in the report's `<stem>.tune.css`); static SVG
  diagrams (`.diagram`) do print.

Styling is three-layer, all siblings of the source, materialized by the
renderer:

- `report-style.css` — framework-managed copy of the base sheet, **reset on
  every render**; never hand-edit it.
- `report-theme.css` — user-owned identity tokens for the folder, seeded once
  (from `workspace/_custom/templates/reports/theme.css` when that exists —
  announce the override when it does), never overwritten.
- `<stem>.tune.css` — per-report hand-tuning delta (page budgets, column
  widths, one-off spacing), seeded once, **never overwritten**, loaded last
  so it wins. Hand-tuning survives every re-render.

Keep all three `<link>` lines from the scaffold and rename the tune link to
match the file's stem — the renderer warns about links to files that don't
exist.

## 3. Render

```bash
uv run python -m superagent.tools.render_report <path>/<file>.html
# useful flags:
#   --watermark "FAMILY ONLY"   footer-left marking (default: none)
#   --force                     re-render even when the PDF is fresh
#   --check                     staleness probe only (exit 1 when stale)
#   --strict                    fail on page-guard warnings
#   --no-prepared-by            drop the byline (default byline comes from
#                               config.yaml profile name/email)
```

The renderer is lazy (skips when the PDF is newer than the HTML and all
three stylesheets), prints page 1 and pages 2+ as two furniture passes,
merges them, and runs a page guard that warns on mixed page sizes or large
blank bands. If Chromium is missing it prints the one-line install command.

The renderer also keeps a managed `render.sh` beside the sources for
standalone rebuild loops (hand-tune `<stem>.tune.css` or the HTML, rebuild
without re-invoking the module path):

```bash
./render.sh                   # render every report in the folder (forced)
./render.sh <stem>            # render one (".html" optional)
./render.sh --live [stem]     # watch sources; re-render on change
```

## 4. Verify and close

1. Confirm the render output line (`rendered <path> (N pages)`) and resolve
   any `guard:` warnings — open the PDF (or raster a page) and eyeball:
   header/footer slots filled, no blank half-pages, no orphaned headings.
2. Re-run the same render command and confirm the `fresh ... (skip...)` line
   — the lazy path is the regression check that the artifact is settled.
3. For Outbox artifacts: append the `outbox-log.yaml` row (create + any later
   stage transition). For domain/project reports: add a dated line to that
   entity's `history.md`.
4. Log the run to `_memory/interaction-log.yaml` (`skill: report`) with the
   artifact path and page count.
