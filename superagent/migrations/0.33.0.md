## Summary

0.33.0 adds two things for agents that run as sessions of their own.

An agent may ask the Updater for a look at named registered sources now: one
message that names them by handle (`Check: watch:<id>`) and says why. The
Updater runs a targeted run, which is no cycle: `watchlist check --requested
--id <id> [--id <id> ...]` takes exactly those sources, leaves their schedule
out and keeps their own limits (throttle, the wait after a failure, the
pack's call budget; a manual-capture source still waits for the owner). The
asker is told the outcome for each source (`skills/update.md` step 12).

The lead and its dev twin take no default model. The lead is the owner's own
session. Its dev twin is started on the model and effort of the session that
starts it, read at that moment. Every other agent keeps the default the
owner sets in `preferences.autocode.models`, and a model named on an agent's
registry row comes first. A subagent's stated default is its parent
session's model; the tier rules of `rules/subagents.md` stay.

Nothing in a workspace needs converting: no file changes shape, and no
setting is read differently for an agent that already runs. This step
advances `workspace/.version` and nothing else. A running agent keeps its
model until it is restarted.
