## Summary

Marker migration for the `0.9.0` release that lands the **branded browser
bundle** in browserctl. The release adds: a new `browserctl icon` command
that builds a dedicated "Superagent Browser" app bundle (APFS clonefile
copy of Playwright's Chromium with its own Dock name and a generated teal
icon, ad-hoc re-signed; `--png` / `--icns` / `--color` / `--name`
overrides), a registry key `app_bundle` that makes every subsequent
`launch` prefer the bundle, and a re-anchored profile theme palette with
teal `#14B8A6` as the first auto-assigned color. Ported from the co-sa
sibling framework's browserctl.

None of the workspace data layout, memory file schemas, or required
config keys change. Existing workspaces keep working without
modification. The bundle itself lives under the machine-local
`~/.browserctl/app/` (never in the repo) and is built lazily on the
first `icon` invocation per machine.

## Revert

1. Write `workspace/.version` back to `0.8.0`. Implementation:
   `tools/version.py.set_workspace_version(workspace, "0.8.0")`.

After revert, no other workspace state needs unwinding — the release
changes only framework files under `superagent/`; nothing under
`workspace/` is touched.

## Notes

- The app bundle is per-machine, disposable state under
  `~/.browserctl/app/`. It is NOT rebuilt by this migration; users opt
  in by running `uv run superagent/tools/browserctl.py icon` once.
  Without it, launches keep using Playwright's stock Chromium exactly
  as before.
- After a `playwright install chromium` update, the bundle points at
  the previous Chromium copy until `icon` is re-run — re-running it is
  the documented refresh path (see `skills/browserctl.md` § Command
  reference).
- Existing profiles keep their already-assigned theme colors; the new
  teal-first palette applies to profiles created after this release.
