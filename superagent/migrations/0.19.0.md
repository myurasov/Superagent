## Summary

0.19.0 introduces the watchlist (`contracts/watchlist.md`): external sources
are registered as `.ref.md` files under `Sources/Watchlist/` carrying a
`watch:` block, and their run state lives in the machine-owned
`_memory/watchlist-state.yaml`. This migration folds every row of the retired
`_memory/data-sources.yaml` into such a ref (cadence and capture mode
preserved verbatim -- a manual source stays manual), moves the old file to
`_memory/_retired/`, relocates every STANDALONE reference file into the
registry as a paused watcher, and adds `preferences.watchlist` to
`config.yaml`. Sidecar refs (metadata for a sibling document, payment
confirmations) never move. Every rewritten or relocated file is checkpointed
under `_memory/_checkpoints/0.19.0/` and every move is recorded in
`_memory/_retired/0.19.0-moves.yaml`, so `revert.py` restores the prior state
byte-for-byte.

## Pre-flight checks

- [ ] Workspace exists at the resolved path.
- [ ] `_memory/config.yaml` is well-formed YAML.
- [ ] `_memory/data-sources.yaml`, `_memory/sources-index.yaml` and
      `_memory/watchlist-state.yaml` (each when present) parse as YAML.
- [ ] Nothing under `_memory/_checkpoints/0.19.0/` from an aborted earlier
      attempt that the user wants to keep -- an existing checkpoint file is
      NOT overwritten (the earliest original wins), which is what makes a
      re-run after a halt safe.

## Migrate

All steps are performed by
`uv run python superagent/migrations/0.19.0/migrate.py --workspace <path>`
(add `--dry-run` to report only). The script is authoritative; the per-step
description below is what it does. The registry folder is
`config.preferences.watchlist.path` when already set, else `Sources/Watchlist/`.

1. **Registry folder.** Create `Sources/Watchlist/` and seed its `README.md`
   from `superagent/templates/folder-readmes/Watchlist.md` (an inline
   fallback text is used when the template is absent).
2. **State file.** Seed `_memory/watchlist-state.yaml` from
   `superagent/templates/memory/watchlist-state.yaml`, else
   `{schema_version: 1, watchers: {}}`.
3. **Fold `data-sources.yaml`.** For every row whose `id` names a shipped
   pack (`simplefin`, `gmail`), write `Sources/Watchlist/<id>.ref.md`:
   `kind: api`, `source: "<id>"`, `related_domain` when derivable
   (`simplefin` -> `finances`), `watch.pack: <id>`, `watch.enabled` /
   `watch.schedule` carried verbatim, `watch.capture_mode` carried verbatim
   (`manual` stays `manual`; the legacy spelling `scheduled` is written as
   `automatic`, and a `disabled` row keeps `enabled: false` with
   `capture_mode: manual`), `watch.evict_after_days: null` (a data feed that
   is quiet is not dead), and every other non-lifecycle key (`auth`,
   `recency_window_days`, `backfill_window_days`, `max_items_per_run`,
   `writes_upstream`, ...) verbatim under `watch.params`. The row's `notes`
   prose becomes the ref body under `# Notes`. Run state moves into
   `watchlist-state.yaml`: `last_ingest` -> `last_success` and `last_harvest`
   (and `last_checked`), `failure_streak` -> `error_streak`, `last_run` ->
   `last_harvest_result`, `status: active|disabled` from `enabled`. A row with
   no shipped pack is left unfolded (it travels with the file in step 4) and
   is listed in the report and by `validate.py`. A ref that already exists is
   never overwritten (re-run safe).
4. **Retire.** Move `_memory/data-sources.yaml` to
   `_memory/_retired/data-sources.yaml` (moved, not deleted).
5. **Relocate standalone refs.** Scan `Sources/**`, `Projects/*/Sources/**`
   and `Projects/*/Resources/**` (skipping the registry and any `_cache/`)
   for `.ref.md` / `.ref.txt` files. A ref is a SIDECAR and stays put when a
   sibling document exists whose name equals the ref filename minus the ref
   suffix (or whose stem does), when its frontmatter carries
   payment-confirmation fields (`payee` / `amount` / `confirmation`), or when
   it is `kind: file` with `source` pointing at a sibling. A ref without
   canonical frontmatter also stays (normalize it before watching). Every
   other ref moves to `Sources/Watchlist/<id>.ref.md`, where `<id>` is the
   stem, kept in the usual Sources naming convention (lowercase, `_` between
   words), with a `watch:` block appended inside the frontmatter --
   `type` mapped from `kind` (`cli` -> `cmd`, `url` -> `url`, `file` ->
   `path`, `manual` / `mcp` / `api` / `vault` -> `subagent`), `enabled:
   false`, and the comment `migrated 0.19.0 -- set enabled: true to start
   watching`. A `subagent` watcher also gets a derived read-only `prompt`
   ("Read <title> at <source>; compare against the previous note ...; return
   ONE line: the delta, or 'no change'. Read-only -- never submit, send, or
   write."), because the loader rejects a `subagent` watcher without one. A
   file already carrying `watch:` keeps it. A source folder left empty by
   the move (e.g. `Sources/Smart_Home/`) is removed -- only when it is
   empty; scan roots are never removed. Then every occurrence of the old
   workspace-relative path in `Domains/*/sources.md` and
   `Projects/*/sources.md` (plus the project-relative form inside the
   owning project's catalogue) is rewritten to the new path, the matching
   `_memory/sources-index.yaml` row has its `path` updated in place and
   **keeps its `id`** (so history and log rows citing `src-...` stay live;
   `sources_index refresh` honours path identity), and `sources_index
   refresh --force` runs so the registry is indexed.
6. **config.yaml.** Insert the `preferences.watchlist` block (`path`,
   `cycles`, `evict_after_days`, `allow_cmd`, `min_check_interval_minutes`)
   at the end of `preferences:` as a text edit that keeps comments; refresh
   top-level `last_updated`. `preferences.ingestion_schedule` is left in
   place (inert, read by nothing -- the 0.8.0 posture for dead preference
   blocks).
7. **world.yaml rebuild.** Checkpoint `_memory/world.yaml`, then run `uv run
   python -m superagent.tools.world --workspace <path> rebuild` (derived; a
   failure is a warning only; `--skip-world` skips it).
8. Advance `workspace/.version` to `0.19.0`.

## Validate

`uv run python superagent/migrations/0.19.0/validate.py --workspace <path>`
runs all of these and exits 0 iff every check passes. Every check is
blocking.

- [ ] `_memory/watchlist-state.yaml` parses and `watchers` is a mapping.
- [ ] Every ref in the registry parses and its `watch:` block names a known
      pack or a shipped detect type (`url`, `path`, `cmd`, `subagent`,
      `gmail`, `harvest`; `index_query` is reserved and rejected).
- [ ] **B4 equality:** for every folded row, the effective `schedule` and
      `capture_mode` (registry override, else pack default) equal the
      pre-migration values read from `_retired/data-sources.yaml`. For a
      workspace whose only enabled source is `simplefin` at `weekly` /
      `manual`, that row must still read `weekly` / `manual`.
- [ ] Rows with no shipped pack are listed as unfolded.
- [ ] `_memory/data-sources.yaml` no longer sits directly under `_memory/`.
- [ ] No sidecar was moved (no relocated ref's original folder holds the
      document it described) and every remaining sidecar has its sibling.
- [ ] No moved ref's old path remains in any `sources.md` catalogue.
- [ ] `config.yaml` carries `preferences.watchlist`.
- [ ] `workspace/.version` reads `0.19.0`; `uv run python -m
      superagent.tools.version check` exits 0.
- [ ] When `superagent.tools.watchlist` is importable, `check --cycle
      daily-update --dry-run` runs clean and dispatches no harvest
      (`summary.harvested == 0`); reported as skipped when the module is not
      shipped.
- [ ] Re-running `migrate.py` reports "nothing to do" (idempotency).

When every check passes, `validate.py` relocates
`_memory/_checkpoints/0.19.0/` to `_memory/_retired/0.19.0-originals/`: the
checkpoint folder exists only while the migration is incomplete, while the
pre-migration originals stay parked next to the ledger so the revert below
remains byte-for-byte (`--keep-checkpoints` skips the relocation).

## Revert

`uv run python superagent/migrations/0.19.0/revert.py --workspace <path>`
(`--dry-run` to preview) performs, in this order:

1. Restore every file under `_memory/_checkpoints/0.19.0/` (or, after a
   successful validate, `_memory/_retired/0.19.0-originals/`) to its original
   relative path (byte-for-byte): the pre-move bytes of each relocated ref
   (recreating a source folder the migration removed), the rewritten
   `sources.md` catalogues, `sources-index.yaml`, `config.yaml` (which drops
   the `preferences.watchlist` block), the pre-rebuild `world.yaml`, and a
   pre-existing `watchlist-state.yaml` if there was one. Edits made after the
   migration to those files are lost -- re-apply them by hand if they matter.
2. Remove the registry copy of every relocated ref and every ref the fold
   generated, as recorded in `_memory/_retired/0.19.0-moves.yaml`. Refs the
   ledger does not know about (authored after the migration) are kept.
3. Move `_memory/_retired/data-sources.yaml` back to `_memory/`.
4. Delete `_memory/watchlist-state.yaml` when the migration seeded it.
5. Remove `Sources/Watchlist/README.md` when the migration seeded it and it is
   unchanged; remove the folder when it is then empty.
6. Remove the ledger and the originals / checkpoint folder; write `0.18.1` to
   `workspace/.version`.
