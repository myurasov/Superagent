## Summary

The `0.12.0` release replaces the gen-1 token-discipline rules with the
leveled gen-2 system: `rules/subagent-bulk-reads.md` becomes
`rules/subagents.md` (bulk-read floor + leveled delegation posture),
`rules/large-file-reads.md` folds into the new `rules/token-economy.md`
(leveled economy + pacing) and retires. Both rules read their dials from
`preferences.token_economy` in `_memory/config.yaml`. An absent block
resolves to the shipped defaults, so this migration is a convenience: it
seeds the block explicitly and renames any user overlay files that extended
the retired rule names, so the overlays keep loading.

## Pre-flight checks

- [ ] The configured workspace path exists and is a directory.
- [ ] `workspace/_memory/config.yaml` is well-formed YAML with a
      `preferences:` mapping.
- [ ] `workspace/.version` reads `0.11.0` (the from-version this migration
      expects).

## Migrate

1. If `workspace/_memory/config.yaml` has no `preferences.token_economy`
   key, insert this block under `preferences:` (skip if the key is already
   present — idempotent):

   ```yaml
   # Token economy (see superagent/rules/token-economy.md + rules/subagents.md).
   token_economy:
     level: auto                   # off | med | full | auto
     subagents: auto               # off | auto | quality | cost
     input_tokens_per_minute: "1m" # integer, or k/m shorthand
   ```

2. If `workspace/_custom/rules/large-file-reads.md` exists and
   `workspace/_custom/rules/token-economy.md` does not, rename the former to
   the latter. If both exist, leave both in place and report the pair to the
   user for a manual merge (do not overwrite or delete either).
3. If `workspace/_custom/rules/subagent-bulk-reads.md` exists and
   `workspace/_custom/rules/subagents.md` does not, rename the former to the
   latter. Same both-exist behavior as step 2.
4. Update `workspace/.version` to `0.12.0`. Implementation:
   `tools/version.py.set_workspace_version(workspace, "0.12.0")`.

## Validate

- [ ] `workspace/.version` reads `0.12.0`.
- [ ] `workspace/_memory/config.yaml` parses and has a
      `preferences.token_economy` mapping (read it back with
      `yaml.safe_load`, not by eye). If step 1 INSERTED the block, its keys
      must read the seeded defaults (`level: auto`, `subagents: auto`,
      `input_tokens_per_minute: "1m"`). If the block pre-existed, do not
      enum-check its values — step 1 left them untouched by design; at most
      WARN on a value outside `off | med | full | auto` /
      `off | auto | quality | cost`.
- [ ] No file named `large-file-reads.md` or `subagent-bulk-reads.md`
      remains under `workspace/_custom/rules/` (unless the both-exist case
      in steps 2–3 was reported for manual merge).
- [ ] Pre-existing `token_economy` values (if any) were left untouched.

## Revert

1. Write `workspace/.version` back to `0.11.0`.
2. If step 1 inserted the `token_economy` block AND it still matches the
   seeded defaults exactly, remove it. If the user has since changed any
   value, KEEP the block — reverting a migration does not discard user
   configuration.
3. Reverse any rename performed in steps 2–3 (`token-economy.md` back to
   `large-file-reads.md`, `subagents.md` back to `subagent-bulk-reads.md`)
   only for files this migration renamed.

## Notes

- The rules work without the seeded block (absent = same defaults); the
  seed only makes the dials visible and editable in place.
- No other workspace data layout, memory file schemas, or required config
  keys change in this release.
