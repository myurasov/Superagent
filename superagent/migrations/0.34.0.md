## Summary

0.34.0 adds three things for agents that run as sessions of their own.

A project agent's registry row may carry an id name (`id_name`): the name its
id is built from once the owner gave the agent another id than its instance
name gives, such as one of a group (`project:<group>:<member>` for the agents
of related projects). Every tool builds that id: `agents id`, the start
prompt, the messages of `tools/autocode.py`, the cap check of a wake, and the
two audits. The instance name stays the agent's name everywhere else: the
registry key, the handle, the project and every tool's argument, so no wake
has to be set again. `agents set <name> --id-name <id name>` records it.

The agent of a parent project records the owner's answers to the asks of its
sub-projects' agents, when he gives them in its session
(`tools/autocode.py answer`). The parent is the `parent` of the project's row
in `_memory/projects-index.yaml`. The tool now refuses every other agent; the
lead and a session that is no registered agent record as before.

A start has an agent write its role's interests onto its row once: the start
prompt carries the step only for a row that has none recorded yet. A later
start leaves the row as it is, so an interest the agent or the owner dropped
stays dropped. `agents interest <agent> --defaults` is unchanged.

Nothing in a workspace needs converting: a row without `id_name` is read as
before, and no file changes shape. This step advances `workspace/.version`
and nothing else.
