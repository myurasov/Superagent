## Summary

0.25.0 gives the framework a roster of agents (`contracts/agents.md`): role
files with duties and dev twins under `superagent/agents/`, ids built from a
configured prefix, and a registry of instances. The Supertailor and Supercoder
role files are gone: the review is the `supertailor-review` skill and
implementing follows `rules/framework-changes.md`. Run-time behavior is
unchanged: no agent runs by itself, and the chat session takes whichever role
the work needs. This migration adds the `preferences.autocode` block to
`config.yaml` (id prefix `sa`, no model, no cost cap) and creates the empty
agent registry `_memory/agents.yaml`. Nothing is deleted and no existing row
changes.

## Pre-flight checks

- [ ] Workspace exists at the resolved path (it has a `_memory/` folder).
- [ ] `_memory/config.yaml` and `_memory/agents.yaml` (when present) parse as
      YAML.
- [ ] No other machine is writing the workspace while the migration runs
      (`rules/concurrent-sessions.md`): run it on one machine and let the sync
      settle before opening the workspace on another.

## Migrate

All steps are performed by
`uv run python superagent/migrations/0.25.0/migrate.py --workspace <path>`
(add `--dry-run` to report only). The script is authoritative; the per-step
description below is what it does.

1. **Config.** Add the `autocode` block at the end of the `preferences`
   mapping of `_memory/config.yaml`, as text: `id_prefix: "sa"`, the `runner`
   and `dev` model defaults (both null, meaning the harness's own default), and
   `daily_usd: null` (no cap). Every other line of the file is untouched, and
   the script checks that the file reads back as the old content plus that one
   key. A config that already has the block is left alone. A config with no
   `preferences` block mapping is left alone too, with a line saying so: the
   tools use the default prefix until the key is set by hand. The inserted
   text is recorded in the ledger `_memory/_retired/0.25.0-ledger.yaml`.
2. **Registry.** Create `_memory/agents.yaml` from the framework template when
   the workspace has none. It holds no agent: a lead or durable role needs a
   row only to carry a setting, and a project agent is added when one is
   wanted (`agents` skill).
3. **Version.** `workspace/.version` advances to `0.25.0`.

Not converted, on purpose: rows of `_memory/supertailor-suggestions.yaml`
written before 0.25.0 have no `agent` field and are read as concerning the
lead. They are never rewritten.

After the migration, set what is yours in `preferences.autocode` (edit the
file in place):

- `id_prefix`, when the default `sa` is not the prefix wanted. A different
  prefix matters when several people share one Autocode server.
- `models.runner` and `models.dev`, when agents should use a model other than
  the harness's default.

`uv run python -m superagent.tools.agents list` then shows the roster with the
ids that result.

## Validate

`uv run python superagent/migrations/0.25.0/validate.py --workspace <path>`
runs all of these and exits 0 iff every check passes.

- [ ] `_memory/config.yaml` parses and gives a valid id prefix.
- [ ] `_memory/agents.yaml` exists with `schema_version` and an `agents` list,
      and every row in it reads.
- [ ] `workspace/.version` reads `0.25.0`.
- [ ] Re-running `migrate.py --dry-run` reports "nothing to do"
      (idempotency).

## Revert

`uv run python superagent/migrations/0.25.0/revert.py --workspace <path>`
(`--dry-run` to preview) performs, in this order:

1. Remove the `autocode` block from `_memory/config.yaml` when the migration
   added it (the ledger says so). The inserted text is removed byte for byte
   when it is unchanged. A block edited since (another prefix, a model) is cut
   out by its shape, and its lines are saved to
   `_memory/_retired/0.25.0-originals/config-autocode.yaml`.
2. Remove `_memory/agents.yaml`: deleted when it names no agent, moved to
   `_memory/_retired/0.25.0-originals/agents.yaml` when it does.
3. Remove the ledger and write `0.24.0` to `workspace/.version`.

The 0.24.0 tools read neither the block nor the registry. An `agent` field on
a suggestion row written under 0.25.0 stays; 0.24.0 ignores it.
