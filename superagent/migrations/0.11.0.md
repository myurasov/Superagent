## Summary

The `0.11.0` release makes Superagent drivable from any `AGENTS.md`-reading
harness (Cursor, Claude Code, Codex CLI, and future CLIs) — an `AGENTS.md`
"Non-Negotiables (Every Harness)" floor, the `unbox` / `sandbox-ladder` /
`run-escalated` rules, a universal harness-setup section, a browserctl
sandboxed-harnesses playbook, fallback one-liners in the read-discipline
rules, and `docs/harness-matrix.md`.

Two of those rules are backed by small workspace registries that the agent
reads once per session (floor item 1):

- `workspace/_memory/unboxed.yml` — pass-through wrappers for name-blocked
  commands (`rules/unbox.md`).
- `workspace/_memory/escalate.yml` — command classes known to require
  escalated execution (`rules/run-escalated.md`).

Both are lazy-created on first use, so seeding them is a convenience, not a
correctness requirement — but seeding gives the floor's session-start read a
stable target and documents the schema in place.

## Pre-flight checks

- [ ] The configured workspace path exists and is a directory.
- [ ] `workspace/_memory/config.yaml` is well-formed YAML.
- [ ] `workspace/.version` reads `0.10.0` (the from-version this
      migration expects).

## Migrate

1. If `workspace/_memory/unboxed.yml` does not exist, copy the seed
   template `superagent/templates/memory/unboxed.yml` into place (header
   comments + empty `wrappers: []` list).
2. If `workspace/_memory/escalate.yml` does not exist, copy the seed
   template `superagent/templates/memory/escalate.yml` into place (header
   comments + empty `entries: []` list).
3. Update `workspace/.version` to `0.11.0`. Implementation:
   `tools/version.py.set_workspace_version(workspace, "0.11.0")`.

## Validate

- [ ] `workspace/.version` reads `0.11.0`.
- [ ] Both registry files exist, parse as YAML, and have the expected
      top-level key (`wrappers` / `entries`).
- [ ] Pre-existing registry files (if any) were left untouched.

## Revert

1. Write `workspace/.version` back to `0.10.0`.
2. For each of the two registry files: if the file still matches the seeded
   empty state exactly (header + empty list), delete it. If it has gained
   real rows since the migration, KEEP it — deleting agent-accumulated
   knowledge is not part of a revert.

## Notes

- The rules work without these files (both are specified as lazy-created);
  the seed only removes the first-use ambiguity.
- No other workspace data layout, memory file schemas, or required config
  keys change in this release.
