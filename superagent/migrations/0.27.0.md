## Summary

0.27.0 lets agents run as sessions of their own, registered with Autocode
(`rules/autocode.md`, `tools/autocode.py`), and adds the `add-agent` skill
for project agents and custom agents. Wake grants are recorded with
`agents grant`, and a wake with no grant never runs
(`agents check ... --wake <name>`). **Nothing runs by itself after this
migration**: the switch it adds, `preferences.autocode.enabled`, is off, and
with it off everything works as in 0.26.0. This migration adds that switch
and the two keys that say when a scheduled update may run. Nothing is deleted
and no existing row changes.

## Pre-flight checks

- [ ] Workspace exists at the resolved path (it has a `_memory/` folder).
- [ ] `_memory/config.yaml` parses as YAML.
- [ ] No other machine is writing the workspace while the migration runs
      (`rules/concurrent-sessions.md`).

## Migrate

All steps are performed by
`uv run python superagent/migrations/0.27.0/migrate.py --workspace <path>`
(add `--dry-run` to report only). The script is authoritative; the per-step
description below is what it does.

1. **Config.** Add three keys to `_memory/config.yaml`, as text, each one
   line at the end of its block: `preferences.autocode.enabled: false`,
   `preferences.update.work_hours: null` and `preferences.update.off_days: []`.
   A key that is already there is left alone. A config without the block is
   left alone, with a line saying so: the tools then use the defaults (the
   switch off, any hour, no off day). Every other line is untouched, and the
   script checks that the file reads back as the old content plus the new
   keys. What it inserted is recorded in the ledger
   `_memory/_retired/0.27.0-ledger.yaml`.
2. **Version.** `workspace/.version` advances to `0.27.0`.

Not converted, on purpose: `_memory/agents.yaml` is not touched. A grant
written from now on carries `duty`, `status` and `approval`; an older `wakes`
entry reads as an active grant.

Turning Autocode mode on is a separate decision of the owner
(`docs/agents.md` § "Turning Autocode mode on"): set
`preferences.autocode.enabled: true`, run the owner-side settings, grant the
wakes, start the agents.

## Validate

`uv run python superagent/migrations/0.27.0/validate.py --workspace <path>`
runs all of these and exits 0 iff every check passes.

- [ ] `_memory/config.yaml` parses.
- [ ] `preferences.autocode.enabled`, when present, is true or false.
- [ ] `preferences.update.work_hours` is a string or null, and `off_days` a
      list.
- [ ] The roster reads without a problem.
- [ ] `workspace/.version` reads `0.27.0`.
- [ ] Re-running `migrate.py --dry-run` reports "nothing to do"
      (idempotency).

## Revert

Stop every agent that runs as a session of its own first
(`uv run python -m superagent.tools.autocode stop <agent>`): the 0.26.0 tools
know nothing of Autocode mode. Then
`uv run python superagent/migrations/0.27.0/revert.py --workspace <path>`
(`--dry-run` to preview) performs, in this order:

1. Remove from `_memory/config.yaml` the keys the migration added (the ledger
   says which): the line of each key, whatever its value is now. A line edited
   since (the switch turned on, work hours set) is saved to
   `_memory/_retired/0.27.0-originals/config-keys.yaml`.
2. Remove the ledger and write `0.26.0` to `workspace/.version`.

Left in place: rows and grants in `_memory/agents.yaml`, and role files under
`workspace/_custom/agents/`. The 0.26.0 tools read the rows and ignore the
extra grant fields.
