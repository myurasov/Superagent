## Summary

0.24.0 makes a workspace safe to open on more than one machine when a
folder-sync tool carries it between them (`rules/concurrent-sessions.md`).
The two logs every session appends to become one file per machine
(`_memory/interaction-log/<machine>.yaml`, `_memory/user-queries/<machine>.jsonl`),
written through `signals log` and the prompt hook and read as one merged view
(`signals log-show`, `log_user_query --show`). New ids carry the machine's
tag, the on-open check stops writing a shared file, and a conflict sweep
(`tools/heal.py`) merges append-only logs and reports every other conflict
copy. This migration creates the per-machine folders, freezes the single log
files in place as read-only history, and removes the on-open nag marker from
`context.yaml`. Nothing is deleted and no row moves.

## Pre-flight checks

- [ ] Workspace exists at the resolved path (it has a `_memory/` folder).
- [ ] `_memory/config.yaml` and `_memory/context.yaml` (when present) parse
      as YAML.
- [ ] No other machine is writing the workspace while the migration runs:
      run it on one machine, let the sync settle, and only then open the
      workspace on the others.

## Migrate

All steps are performed by
`uv run python superagent/migrations/0.24.0/migrate.py --workspace <path>`
(add `--dry-run` to report only). The script is authoritative; the per-step
description below is what it does.

1. **Folders.** Create `_memory/interaction-log/`, `_memory/user-queries/` and
   `_memory/machines/`. The tools write one log file and one beat file per
   machine there, each on its first use.
2. **Freeze the single log files.** `_memory/interaction-log.yaml` and
   `_memory/user-queries.jsonl`, whichever exist, stay where they are, byte
   for byte, and are read-only history from here on (they remain part of the
   merged views). Their row count, size and last id go into the marker
   `_memory/interaction-log/_frozen.yaml`. `heal strays` uses the marker to
   find a row that was still appended to the old file afterwards, and
   `doctor` moves such a row into the machine's own file.
3. **`context.yaml`.** Remove the top-level `refresh_suggested` key together
   with the comment lines directly above it. The on-open check keeps the day
   it last nagged in `~/.superagent/state/` on each machine instead, so
   opening a session writes no shared file. The removed lines are recorded in
   the ledger `_memory/_retired/0.24.0-ledger.yaml`. Every other line of the
   file is untouched.
4. **Version.** `workspace/.version` advances to `0.24.0`.

Not converted, on purpose: ids. Ids written before 0.24.0
(`ilog-2026-08-31-003`, `task-20260831-001`) stay valid forever and are never
renamed; only new ids carry the machine tag.

Machine-local, outside the workspace and not part of this migration: each
machine fixes its name in `~/.superagent/machine.json` the first time a tool
needs it (from the host name; `uv run python -m superagent.tools.machines name --set <name>`
changes it).

## Validate

`uv run python superagent/migrations/0.24.0/validate.py --workspace <path>`
runs all of these and exits 0 iff every check passes.

- [ ] The three per-machine folders exist under `_memory/`.
- [ ] When the workspace has a single log file, the freeze marker parses and
      its counts do not exceed what the files hold now.
- [ ] `context.yaml` parses and carries no `refresh_suggested` key.
- [ ] The merged interaction log reads with no unreadable file.
- [ ] `workspace/.version` reads `0.24.0`.
- [ ] Re-running `migrate.py --dry-run` reports "nothing to do"
      (idempotency).

Then run `uv run python -m superagent.tools.heal sync-check` and surface what
it prints: the sync settings that differ from the safe ones. Changing a sync
setting is outside the workspace and needs the user's approval for each one.

## Revert

`uv run python superagent/migrations/0.24.0/revert.py --workspace <path>`
(`--dry-run` to preview) performs, in this order:

1. Append every row of every `_memory/interaction-log/<machine>.yaml` to the
   single `_memory/interaction-log.yaml`, oldest first, and every line of
   every `_memory/user-queries/<machine>.jsonl` to `_memory/user-queries.jsonl`
   (the 0.23.0 tools read only those two files). Rows already present are not
   added twice.
2. Move the per-machine log files to `_memory/_retired/0.24.0-originals/`,
   remove the freeze marker and the beat files, and remove the three folders
   when they are empty.
3. Put the `refresh_suggested` lines back into `context.yaml` from the ledger
   and remove the ledger.
4. Write `0.23.0` to `workspace/.version`.

Run the revert on one machine with the others closed, like the migration. Ids
minted with a machine tag keep it; the 0.23.0 tools read them as plain ids.
