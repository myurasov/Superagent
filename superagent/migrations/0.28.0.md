## Summary

0.28.0 adds the `start` skill: "start superagent" asks in question cards
whether to turn Autocode mode on, shows the proposed settings for the owner
to approve or change, asks which other agents to start, and then does the
writes itself (`tools/autocode.py setup enable`, `setup apply`, `mark`). The
owner edits no file and runs no command. Nothing in an existing workspace
needs converting: the settings it writes use keys that 0.27.0 already put
into `config.yaml`, and the registry rows and grants keep their shape. This
step advances `workspace/.version` and nothing else, and nothing starts
running by itself.

One thing changes for a workspace whose agents already run as sessions: the
check line of a wake is now `sh superagent/tools/wake_check.sh <agent>
[<duty>] --wake <name>` (it finds `uv` on any `PATH` and puts the daily cost
cap in front of the duty's check). A wake set with the 0.27.0 line keeps
working; "start superagent" sets the wakes again with the new line.

      0.27.0 before this step.
- [ ] `uv run python -m superagent.tools.validate` exits 0 (warnings allowed).

## Migrate

1. No data changes. The `migrate` skill advances `workspace/.version` to
   `0.28.0` once Validate passes.

## Validate

- [ ] `uv run python -m superagent.tools.validate` exits 0.
- [ ] `uv run python -m superagent.tools.autocode setup` exits 0 (it reads the
      roster, the config and the cadences, and writes nothing).
- [ ] Idempotent: re-running this step changes nothing.

## Revert

1. Stop every agent that runs as a session of its own first ("stop
   superagent"), since a wake set by 0.28.0 calls `tools/wake_check.sh`.
2. Set `workspace/.version` back to `0.27.0`:
   `uv run python -m superagent.tools.version set 0.27.0`. Settings, rows and
   grants written by "start superagent" are read by 0.27.0 as they are.
