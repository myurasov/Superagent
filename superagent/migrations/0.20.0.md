## Summary

0.20.0 retires the pull-on-demand reference model: a `.ref.md` is a watcher
definition and nothing else (`ref_version: 2`, `contracts/watchlist.md` § 2).
This migration converts every registry ref to schema 2 by text edit (legacy
`kind` / `source` / `ttl_minutes` / ... keys go; a bare watcher's locator moves
into `watch:`), renames registry files to Title_Case (`Simplefin.ref.md`;
the id stays the lowercase stem), renames document sidecars from
`<doc>.<ext>.ref.md` to `<doc>.<ext>.meta.md` so the "every `.ref.md` is a
watcher" rule has no exception, rewrites catalogue rows and index paths (ids
kept), applies the user-directed SimpleFIN cadence (daily / automatic), and
removes an empty `Sources/_cache/`. Every rewritten or renamed file is
checkpointed under `_memory/_checkpoints/0.20.0/` and every change is recorded
in `_memory/_retired/0.20.0-moves.yaml`, so `revert.py` restores the prior
state byte-for-byte.

## Pre-flight checks

- [ ] Workspace exists at the resolved path.
- [ ] `_memory/config.yaml`, `_memory/sources-index.yaml` and
      `_memory/watchlist-state.yaml` (each when present) parse as YAML.
- [ ] Nothing under `_memory/_checkpoints/0.20.0/` from an aborted earlier
      attempt that the user wants to keep -- an existing checkpoint file is
      NOT overwritten (the earliest original wins), which is what makes a
      re-run after a halt safe. A `<name>.ref.md.0-20-0.renaming` file left
      in the registry by a halt between the two steps of a case-only rename
      is completed on the next run.

## Migrate

All steps are performed by
`uv run python superagent/migrations/0.20.0/migrate.py --workspace <path>`
(add `--dry-run` to report only). The script is authoritative; the per-step
description below is what it does. The registry folder is
`config.preferences.watchlist.path` when set, else `Sources/Watchlist/`.

1. **Registry refs to schema 2** (text-level edits; every other line, comment
   and the markdown body are preserved). For every `<registry>/*.ref.md`
   (`README.md` is not one): set `ref_version: 2`; cut the legacy top-level
   keys `kind`, `source`, `ttl_minutes`, `sensitive`, `auth_ref`,
   `chunk_for_large`, `normalized_at`. A bare watcher (no `watch.pack`) with
   `watch.type` but no locator inside `watch:` gets the old `source` as its
   locator, right under `type:` -- `cmd` -> `watch.cmd`, `url` -> `watch.url`,
   `path` -> `watch.path`; a `subagent` without `watch.prompt` gets the
   derived read-only prompt 0.19.0 used. A ref with neither `watch.type` nor
   `watch.pack` that relied on kind-to-type defaulting (`url` -> `url`, `cli`
   -> `cmd`, `file` -> `path`, `manual` -> `subagent`) gets an explicit
   `watch.type` (and a `watch:` block when it had none). A pack instance
   simply drops `source` (pack instances carry their locator in
   `watch.params`). Schema 2 also rejects top-level keys it does not know
   (`category`, `params`, ...): those entries -- together with a non-empty
   `auth_ref` and a `source` that was neither moved nor the pack's own id --
   are cut from the frontmatter and appended verbatim to the body in a fenced
   YAML block under the marker `<!-- 0.20.0: frontmatter entries outside
   ref_version 2, kept verbatim; not read by the tool -->`, so the ref loads
   and nothing the user wrote is lost. A ref whose type cannot be derived
   (`kind: api|mcp|vault` with no `watch.type` / `watch.pack`) is left at
   schema 1, reported, and fails `validate.py` until fixed by hand. Every
   dropped value is recorded in the ledger (`converted[].dropped`).
2. **Title_Case filenames.** `<stem>.ref.md` becomes
   `<Title_Case(id)>.ref.md` where `id` = stem lowercased and `Title_Case`
   capitalizes the first letter of every `_`- or `-`-delimited token
   (`simplefin.ref.md` -> `Simplefin.ref.md`, `home_assistant-hub.ref.md`
   -> `Home_Assistant-Hub.ref.md`; `tools/watchlist.py` `title_case` /
   `id_from_stem`). A case-only rename goes through a temp name
   (`<new>.ref.md.0-20-0.renaming`) so it lands on the case-insensitive macOS
   filesystem. A rename whose target name is already taken by another file
   (two watchers sharing an id) is skipped and reported. Every
   `Domains/*/sources.md` / `Projects/*/sources.md` occurrence of the old path
   is rewritten, and the `_memory/sources-index.yaml` row has its `path`
   rewritten in place and **keeps its `id`** (0.19.0's path-identity rule in
   `sources_index refresh` carries it forward). An index row whose path
   differs from the on-disk name only by case (the file was already
   Title_Case) is aligned the same way (ledger `index_paths`). Catalogue rows
   naming a registry path no file backs are reported, not touched. A file in
   the registry that is not a `.ref.md` (and not `README.md`) is not a
   watcher: it is reported as a note ("not a .ref.md -- not a watcher; rename
   it to `<Title_Case>.ref.md` or move it out of the registry") and left as
   is -- the loader and `sources_index refresh` warn about it the same way.
3. **Sidecars.** Every `.ref.md` under `Sources/`, `Projects/*/Sources/` and
   `Projects/*/Resources/` outside the registry (and outside any `_cache/`)
   is classified: a SIDECAR -- a sibling document exists (`<doc>.<ext>.ref.md`,
   or `<stem>.ref.md` beside `<stem>.<ext>`), or `kind: file` points at a
   sibling, or payment-confirmation fields (`payee` / `amount` /
   `confirmation`) are present -- is renamed to `<doc>.<ext>.meta.md` (the
   document's full filename plus `.meta.md`; a payment confirmation with no
   document beside it becomes `<stem>.meta.md`). Bytes are unchanged. The
   old path (and its project-relative form inside the owning project's
   catalogue) is rewritten in every catalogue; on a catalogue line naming the
   document, the shorthand `` `.ref.md` `` becomes `` `.meta.md` ``; an index
   row at the old path has its `path` rewritten in place (id kept). Any other
   `.ref.md` is a STRAY: reported (not moved) and blocking in `validate.py`
   until moved into the registry or renamed by hand. `.ref.txt` files are
   reported as no longer recognized and left alone.
4. **SimpleFIN cadence (user-directed).** The registry ref with `watch.pack:
   simplefin` gets `schedule: daily`, `capture_mode: automatic`, `cycles:
   [daily-update]` as text edits inside its `watch:` block (inline comments
   kept; a block-form `cycles` list collapses onto the key line). The
   previous values are recorded in the ledger (`cadence[].previous`) and
   the checkpointed bytes restore them on revert. This is the ONE place a
   migration changes a cadence, and only because the user asked for it
   (`tasks/2026/09/2026-09-07-watchlist-design/plan.md` § 15): 0.19.0's rule
   that the tool never widens a cadence on its own initiative still holds.
   Budget (24 calls / day, 60 min) is unchanged; `harvest --id simplefin`
   remains the on-demand path.
5. **`Sources/_cache/`.** Removed only when it is empty (a lone `.DS_Store`
   counts as empty). A non-empty cache folder is kept and reported.
   `config.yaml` is not edited: `preferences.sources.cache_*` keys become
   inert (nothing reads them; the 0.8.0 posture for dead preference blocks)
   and are reported as such.
6. **Derived data + version.** `sources_index refresh --force` runs when any
   ref, sidecar or index row changed (stray / orphan warnings from the index
   are echoed). `_memory/world.yaml` is checkpointed, then
   `uv run python -m superagent.tools.world --workspace <path> rebuild` runs
   (derived; a failure is a warning only; `--skip-world` skips it).
   `workspace/.version` advances to `0.20.0`. The machine-owned
   `_memory/watchlist-state.yaml` is never written: the migration does not
   edit it and validate's dry run passes `--no-harvest`, so nothing in the
   run mutates it (only the 0-byte `.watchlist-state.lock` may appear).

## Validate

`uv run python superagent/migrations/0.20.0/validate.py --workspace <path>`
runs all of these and exits 0 iff every check passes. Every check is
blocking.

- [ ] Every registry ref parses with `ref_version: 2`, carries none of the
      legacy keys and no key outside schema 2, and has a `watch:` mapping.
- [ ] `superagent.tools.watchlist.load_registry` loads the registry with
      zero errors (packs discovered from `superagent/watchers/` +
      `_custom/watchers/`).
- [ ] Every registry filename is `Title_Case(id) + .ref.md` for its lowercase
      id, and ids are unique.
- [ ] No `.ref.md` exists outside the registry under `Sources/`,
      `Projects/*/Sources/`, `Projects/*/Resources/` (`.ref.txt` leftovers
      are noted, not failed).
- [ ] Every `.meta.md` sidecar sits beside its document (a payment
      confirmation with no document is accepted with a note).
- [ ] No renamed ref or sidecar path from the ledger remains in any
      `sources.md` catalogue.
- [ ] Every renamed `sources-index.yaml` row kept its id (and no present row
      remains at the old path).
- [ ] The SimpleFIN ref reads `schedule: daily`, `capture_mode: automatic`,
      `cycles: [daily-update]` (pass with a note when no SimpleFIN ref
      exists).
- [ ] `Sources/_cache/` is absent or non-empty.
- [ ] `workspace/.version` reads `0.20.0`; `uv run python -m
      superagent.tools.version check` exits 0 (skipped with a note while the
      framework's `pyproject.toml` still predates 0.20.0; when a newer
      framework is installed and the workspace reads `0.20.0`, the tool's
      "next migration pending" is the expected mid-chain answer).
- [ ] `watchlist check --cycle daily-update --dry-run --no-harvest --workspace
      <path>` exits 0 with `summary.errors == 0` and `summary.harvested == 0`
      (the loader errors would surface in `summary.errors`). `--no-harvest`
      keeps the check offline-safe: SimpleFIN's harvest is its detect, so a
      plain dry run with automatic capture would make a real API request,
      spend budget, persist counters, and fail on a machine without network
      or credentials. Nothing in validate writes `watchlist-state.yaml`.
- [ ] Re-running `migrate.py --dry-run` reports "nothing to do"
      (idempotency).

When every check passes, `validate.py` relocates
`_memory/_checkpoints/0.20.0/` to `_memory/_retired/0.20.0-originals/`: the
checkpoint folder exists only while the migration is incomplete, while the
pre-migration originals stay parked next to the ledger so the revert below
remains byte-for-byte (`--keep-checkpoints` skips the relocation).

## Revert

`uv run python superagent/migrations/0.20.0/revert.py --workspace <path>`
(`--dry-run` to preview) performs, in this order:

1. Rename every registry ref the migration retitled back to its
   pre-migration name (ledger `renamed`), through a temp name for case-only
   renames.
2. Rename every `.meta.md` sidecar the migration produced back to its
   `.ref.md` name (ledger `sidecars`).
3. Restore every file under `_memory/_checkpoints/0.20.0/` (or, after a
   successful validate, `_memory/_retired/0.20.0-originals/`) to its original
   relative path byte-for-byte: the schema-1 bytes of every converted ref
   (which also restores the pre-migration SimpleFIN cadence), the rewritten
   catalogues, `sources-index.yaml` and the pre-rebuild `world.yaml`. Edits
   made after the migration to those files are lost -- re-apply them by hand
   if they matter.
4. Recreate `Sources/_cache/` when the migration removed it (ledger
   `removed_dirs`).
5. Remove `_memory/.watchlist-state.lock` when it did not exist before the
   migration (the validate dry-run creates it).
6. Remove the ledger and the originals / checkpoint folder; write `0.19.0`
   to `workspace/.version`.
