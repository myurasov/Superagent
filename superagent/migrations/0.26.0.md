## Summary

0.26.0 splits fetching from telling (`contracts/update-loop.md`). The new
`update` skill brings the stores up to date (the watchers that are due, the
drop folders, capture, reconcile, tasks; the full tier adds the transaction
reconcile, project drift and the derived views) and renders no briefing. The
new `brief` skill reads the stores and reports, and fetches nothing. The four
cadence skills (`daily-update`, `whatsup`, `weekly-review`, `monthly-review`)
keep their names and become entry points: `update`, then `brief`. One update
cycle runs at a time per machine (`tools/lock.py`), each watcher runs by its
own schedule (`watchlist check --due`), a question a run may not ask in chat
goes to the asks queue (`_memory/asks.yaml`, `tools/asks.py`), and a duty is
due when its stamp is older than its latest scheduled time.

This migration adds the two update cadences and the `preferences.update`
block to `config.yaml`, and creates the empty asks queue. Nothing is deleted
and no existing row changes.

## Migrate

All steps are performed by
`uv run python superagent/migrations/0.26.0/migrate.py --workspace <path>`
(add `--dry-run` to report only). The script is authoritative; the per-step
description below is what it does.

1. **Cadences.** Add `update_light: "every 30 minutes"` and
   `update_full: "06:00"` at the end of `preferences.cadences` in
   `_memory/config.yaml`, as text. A key that is already there is left alone.
   A config with no `cadences` block is left alone, with a line saying so: the
   tools then use the framework defaults.
2. **Drop folders.** Add the `update` block at the end of the `preferences`
   mapping, as text: `drop_folders: []`, meaning `Inbox/` is the only drop
   folder. A config that has the block is left alone.
3. **Asks queue.** Create `_memory/asks.yaml` from the framework template when
   the workspace has none. It holds no ask.
4. **Version.** `workspace/.version` advances to `0.26.0`.

Every other line of `config.yaml` is untouched, and the script checks that the
file reads back as the old content plus the new keys. What it inserted is
recorded in the ledger `_memory/_retired/0.26.0-ledger.yaml`.

Not converted, on purpose:

- `context.yaml` is not touched. The stamps of the update duties
  (`last_runs.update_light`, `last_runs.update_full`) appear on their first
  run.
- A watcher keeps its `cycles` and `schedule`. `watchlist check --due` reads
  them as the watcher's own period (daily 1 day, weekly 7, monthly 30).
- Interaction-log rows written by the cadence skills before 0.26.0 keep their
  `skill` (`daily-update`, `weekly-review`, ...). New briefings log as
  `skill: brief` and new update cycles as `skill: update`.

After the migration, set what is yours (edit the file in place):

- `preferences.update.drop_folders`, when documents are dropped in a folder
  outside the workspace (a folder a sync tool shares between machines).
- `preferences.cadences.update_full`, when the full tier should run at another
  time of day.

An overlay rule that tells a cadence skill to do something "before writing the
briefing" still holds: the entry points run `update` first, and that is where
fetching and filing happen.

## Validate

`uv run python superagent/migrations/0.26.0/validate.py --workspace <path>`
runs all of these and exits 0 iff every check passes.

- [ ] `_memory/config.yaml` parses.
- [ ] The cadences `update_light` and `update_full` resolve to a schedule.
- [ ] `preferences.update.drop_folders`, when present, is a list.
- [ ] `_memory/asks.yaml` exists with `schema_version` and an `asks` list, and
      every row in it reads.
- [ ] Every role reads and every duty has a stamp key.
- [ ] `workspace/.version` reads `0.26.0`.
- [ ] Re-running `migrate.py --dry-run` reports "nothing to do"
      (idempotency).

## Revert

`uv run python superagent/migrations/0.26.0/revert.py --workspace <path>`
(`--dry-run` to preview) performs, in this order:

1. Remove from `_memory/config.yaml` what the migration added (the ledger says
   what): the two cadence keys and the `update` block. Inserted text that is
   unchanged is removed byte for byte. Text edited since (another time, a drop
   folder) is cut out by its shape, and its lines are saved to
   `_memory/_retired/0.26.0-originals/`.
2. Remove `_memory/asks.yaml` when the migration created it: deleted when it
   holds no ask, moved to `_memory/_retired/0.26.0-originals/asks.yaml` when it
   does.
3. Remove the ledger and write `0.25.0` to `workspace/.version`.

Left in place: the stamps `update_light` / `update_full` in `context.yaml`,
and the fields `last_dispatched` / `last_change_note` in
`watchlist-state.yaml`. The 0.25.0 tools ignore them.
