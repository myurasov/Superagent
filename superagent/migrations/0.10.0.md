## Summary

Marker migration for the `0.10.0` release, which changes browserctl's
machine-local behavior in three ways:

1. **Private home** — browserctl state moves from the machine-shared
   `~/.browserctl/` to `~/.superagent/browserctl/` ($SUPERAGENT_HOME
   aware). The shared home let one framework's `app_bundle` registry key
   hijack another framework's launches. `$BROWSERCTL_HOME` remains the
   explicit override.
2. **Lazy bundle auto-build** — `launch` builds the branded "Superagent
   Browser" app bundle automatically on macOS when it is missing (fresh
   install, wiped state, or the recorded Chromium source was removed).
   No manual `icon` run needed; failures fall back to stock Chromium.
3. **Tab hygiene** — before boot, session/crash restore is disabled in
   the profile's Preferences; after boot, auto-opened extra tabs are
   closed (a launch always starts with exactly one tab); `stop` closes
   all tabs before closing the browser.

None of the workspace data layout, memory file schemas, or required
config keys change.

## Migrate

1. Update `workspace/.version` to `0.10.0`. Implementation:
   `tools/version.py.set_workspace_version(workspace, "0.10.0")`.

## Validate

- [ ] `workspace/.version` reads `0.10.0`.
- [ ] `workspace/_memory/config.yaml` is still readable as YAML.
- [ ] No other files under `workspace/` were modified by this
      migration.

## Revert

1. Write `workspace/.version` back to `0.9.2`.

After revert, no other workspace state needs unwinding — the release
changes only framework files under `superagent/`; nothing under
`workspace/` is touched.

## Notes

- **Existing machines are NOT auto-migrated** to the new home. Options:
  (a) do nothing — profiles re-create clean at
  `~/.superagent/browserctl/` and logins are re-entered once; or
  (b) move `~/.browserctl/profiles/<project>/` +
  the matching `state.json` rows (plus `logs/`, `out/<project>/`, and
  `app/`) into `~/.superagent/browserctl/`; or (c) set
  `BROWSERCTL_HOME=~/.browserctl` to keep the legacy shared home.
- Frameworks still using the shared `~/.browserctl/` (co-sa, Solaris)
  are unaffected — their profiles stay where they are; only
  Superagent's rows/dirs move.
- Existing per-app skills under `workspace/_custom/skills/` that
  hardcode `~/.browserctl/out/...` paths keep working only via
  `$BROWSERCTL_HOME`; update them to `~/.superagent/browserctl/out/...`
  (the shipped `browserctl-irs` skill was updated in-repo... it lives in
  the workspace — updated by hand on the maintainer machine).
