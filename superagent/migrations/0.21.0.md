## Summary

0.21.0 is the second prune (the 0.8.0 prune is the model): twelve skills that
real workloads never exercised are retired -- `handoff`, `baton`, `workbooks`,
`inbox-triage`, `email-refresh`, `triage-overdue`, `audit`, `events`, `tags`,
`follow-up`, `home-maintenance`, `vehicle-log` -- together with the
`render_workbooks.py` and `inbox_triage.py` tools, the `surfacing` and
`inbox-triage` contracts, and the `openpyxl` dependency. The stores and tools
behind `audit` / `events` / `tags` stay (`tools/audit.py`,
`tools/events_derive.py`, `tools/log_window.py`, `_memory/tags.yaml`); overdue
triage lives on as a mode of `todo`; vehicle and home events are a
`history.md` append inside `log-event`. Workspace-side, the artifacts those
tools produced are retired: every rendered workbook under `Domains/<Name>/`
(plus its `.xlsx.meta.yaml` render-cache sidecar) and the inbox-triage decision
log. They are MOVED, never deleted, so revert is a move back. `Inbox/` itself
and every user file in it are untouched; `config.yaml` is not edited.

## Migrate

All steps are performed by
`uv run python superagent/migrations/0.21.0/migrate.py --workspace <path>`
(add `--dry-run` to report only). The script is authoritative; the per-step
description below is what it does.

1. **Rendered workbooks.** For every folder directly under `Domains/`, every
   `<stem>.xlsx` directly inside it is classified: a **domain workbook** when
   `<stem>` lowercased equals the folder name lowercased
   (`Domains/Home/home.xlsx`); a **per-entity workbook** when a sibling
   `<stem>.xlsx.meta.yaml` render-cache sidecar exists (the retired tool
   wrote one beside every workbook it rendered); anything else is a user
   spreadsheet and is reported, not moved. Each rendered workbook and its
   sidecar (an orphan sidecar too) is moved to
   `_memory/_checkpoints/0.21.0/<same relative path>` and recorded in the
   ledger `_memory/_retired/0.21.0-moves.yaml` (`moved[]`: path, kind, size,
   sha256).
2. **Inbox-triage state.** `_memory/inbox-log.yaml` and the pre-0.17.0
   `Inbox/_processed.yaml`, whichever exist, move the same way. Nothing else
   under `Inbox/` is touched: the folder stays as a plain drop folder.
3. **`config.yaml` is not edited.** `preferences.workbooks` and
   `preferences.inbox_triage` become inert (nothing reads them; the 0.8.0
   posture for dead preference blocks) and are reported as such.
4. **Version.** `workspace/.version` advances to `0.21.0`.

## Validate

`uv run python superagent/migrations/0.21.0/validate.py --workspace <path>`
runs all of these and exits 0 iff every check passes.

- [ ] No rendered workbook (domain-named, or with a `.xlsx.meta.yaml`
      sidecar) and no `.xlsx.meta.yaml` remains directly inside any
      `Domains/<Name>/` folder (user spreadsheets are noted, not failed).
- [ ] Neither `_memory/inbox-log.yaml` nor `Inbox/_processed.yaml` exists.
- [ ] The ledger parses; every `moved[]` row is absent from its live path and
      present -- with the recorded sha256 -- in exactly one of
      `_memory/_checkpoints/0.21.0/` or `_memory/_retired/0.21.0-originals/`.
- [ ] `workspace/.version` reads `0.21.0`; `uv run python -m
      superagent.tools.version check` exits 0 (skipped with a note while the
      framework's `pyproject.toml` still predates 0.21.0; when a newer
      framework is installed and the workspace reads `0.21.0`, "next
      migration pending" is the expected mid-chain answer).
- [ ] Re-running `migrate.py --dry-run` reports "nothing to do"
      (idempotency).

When every check passes, `validate.py` relocates
`_memory/_checkpoints/0.21.0/` to `_memory/_retired/0.21.0-originals/`: the
checkpoint folder exists only while the migration is incomplete, while the
retired originals stay parked next to the ledger so the revert below remains
byte-for-byte (`--keep-checkpoints` skips the relocation).

## Revert

`uv run python superagent/migrations/0.21.0/revert.py --workspace <path>`
(`--dry-run` to preview) performs, in this order:

1. Move every file under `_memory/_checkpoints/0.21.0/` (or, after a
   successful validate, `_memory/_retired/0.21.0-originals/`) back to its
   original relative path, byte-for-byte. A live file that has since appeared
   at that path with different bytes is never overwritten: it is reported and
   the parked original stays where it is.
2. Remove the ledger and the (now empty) originals / checkpoint folder.
3. Write `0.20.1` to `workspace/.version`.
